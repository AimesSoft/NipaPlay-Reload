## 2. 决策

1. **设备名放在剧照下面的文字行，不压在剧照上。** 剧照上已经有集号、进度条和当前集的白框，再加一个角标会和“新”这类标签混在一起。时长旁边的位置读起来像“这一集的属性”，和常见媒体库把版本、清晰度写在元信息行的做法一致。
2. **图标用 Finder 里网络上另一台电脑的样子（屏幕加底座）。** 工作站可能没有界面，但“另一台电脑”是最普遍的读法。图标和名字之间不加任何连接词。
3. **离线时设备名不另变淡。** 第一版让离线设备的名字从 p3 变成 p4，但这也算新的离线样式，收窄后去掉了，统一用 p3。
4. **`DeviceMark` 做成一段富文本，图标是行内的 `WidgetSpan`。** 这样放进剧集卡那一行时不需要 `Flexible`，标题仍然占满剩余宽度；在片库的窄卡片里，名字太长会以省略号结尾。
5. **`library` 调试操作直接读 `NextUiData`。** 不在页面里加调试接口，页面文件的改动可以更少。
6. **能力覆盖**：设备名只是展示，切换在线状态只存在于假数据，用户和 Agent 之间都没有新增可做的操作，所以没有新的 Action。

### 意外和没做完的

- **热重载没送进早先的改动**：`flutter attach` 以附加时的源码为基准，附加之前改的文件不会被重载（Y5 也遇到过）。touch 这些文件后重载了 12 个库，之后的观察都在这之后。
- **最终构建上的详情、离线和恢复验证受遮挡影响**（详见本节末尾的“最终构建验证”）：

  - 我试过在调试扩展里加一个兜底：被挡时用定时器画帧。但被挡后应用生命周期进入 hidden，`framesEnabled` 为假，根本不会排帧，兜底不起作用。已经撤回，代码里没有留下。
  - 遮挡期间的观察，是在热重载后的实例上做的，那时的界面代码和最终版本相同。遮挡解除后，已在最终构建上补拍，证据图也已替换，见下文。片库那几张来自第一次最终构建。
- **第一次最终构建的运行里有 10 条 `RenderFlex overflowed`**（28 和 7 像素）。全局错误处理吞掉了堆栈，之后几次启动都没有复现，静止的截图里也没有溢出条纹。我推断原因是：缩小窗口时网格行高立刻变小，而 `PosterCard` 的海报高度是 400ms 的 `AnimatedContainer`，过渡期间会短暂溢出。从 1100 缩到 1000 时海报高度差约 30pt，和 28 吻合。原来按宽高比排布的片库也会这样。这一点没有确认。

## 4. 问题（需要主控决定）

1. **设备离线时，详情页 ⋯ 菜单有两处会误导。** 这是现有逻辑把“离线”和“没下载”都当成 `!playable` 造成的：
   - “下载全部”（`_missing`）把离线设备上的集算作缺失。紫罗兰离线时，菜单只剩“下载全部”，点了会请 Nipa 把旧笔记本上已有的 13 集再下载一遍。改法是一行：`!e.playable && e.device == null`。
   - 标记看过（`_seasonOnDisk`）只统计能播的集。工作站离线时，莉可丽丝的菜单变成“这一季标成没看过”，依据只是本机看完的 1–4 集；“第 5 集看过了”也消失了。改法是把条件换成 `e.playable || e.device != null`。

   按收窄后的范围，这两处我都没改。要修吗？
2. **next 所在设备离线时，详情页主按钮按现有逻辑直接消失。** 设备掉线或回来时，“问 Nipa”和 ⋯ 会左右跳一下。第一版的做法是让按钮留在原位、变淡、不能按，已按要求撤回。保持现状吗？
3. **`library_page.dart` 留在工作区的改动**，等书架式片库定下来以后，保留还是回退？另外，现有片库页滚动时顶栏没有底色，作品标题会从“首页 发现”下面穿过（`library-1000-bottom.jpg` 顶部）。这是原来就有的，重新设计时可以一起考虑。
4. **对约定的意见**：
   - 详情页和剧集卡用 `UiEpisode.device` 加 `playable` 已经够了，界面可以用 `device?.online == false` 区分“离线”和“没下载”，不需要新字段。
   - 只看 `UiWork`，片库分不清“只在离线设备上”和“本机还有能播的集”：`devices` 只说还有哪些设备，不说本机有没有。如果新片库要按原需求让离线设备独有的作品变暗，要么逐部读 `episodes()`，要么给作品加一个“现在有没有能播的集”的事实，由你决定。
5. **安静实验实例会被完全遮住。** 被别的窗口（这次是全屏的 Cua Driver）完全盖住时，实例不出帧，调试扩展会挂起，截图停在最后一帧。要不要在实验基础设施里处理？比如让安静实例被遮挡时也保持出帧，这属于 Classic 原生代码和实验基础设施，本次没有动。或者约定实验时不要开全屏覆盖窗口。
