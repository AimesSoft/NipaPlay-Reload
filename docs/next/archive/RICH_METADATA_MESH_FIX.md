# 丰富元数据导致远端不可播：2026-10-27

## 观察

Mac 可成功调用 Windows 的 `mesh.devices`，但既有远端剧集的
`media.library.readable` 返回 `Source device is offline`。
Mac 的已保存目录约 1.8 MB，仍是旧元数据。工作站现有 TMDB 快照包含
201、299 名演员；Bangumi 快照包含 25–49 名角色，单份最大约 501 KB。

## 代码中的失败路径

`LibraryProjection.page` 的旧协议不能拆分单条记录，而且按累计页大小检查
512 KiB 上限。完整来源快照与合并字段在作品记录中同时携带，丰富资料后
可以超过这一限制。服务器拒绝目录页；接收端 `MeshLibrary._refresh` 将
该来源标为 offline，因而整库远端剧集变为不可播。

普通 RPC 也有 1 MiB 原生帧限制。较大的身份、元数据批量查询响应会在
请求已发送后传输失败，产生 outcome_unknown。初始写入可能已经完成，不能
通过盲目重复原操作解决。

## 修复

- 目录协商 `json-base64-v1` 字节分页，允许在单条记录内部拆分；UTF-8
  拼接完成后再解码，先收全且版本一致后才发布新目录。兼容旧的记录分页来源。
- 大 RPC 响应保留短期、绑定调用设备的 continuation。分块读取和 SHA256
  验证完整结果，不重复执行原 Action；授权、吊销和重放检查照常执行。
- `media.library.refresh` 公开每个来源的同步失败，保留结构化原因。
- 分页固定使用已发布的不可变目录（保留最近 4 个版本），播放进度变化不会
  打断正在进行的传输。目录失败后独立做一次经过认证的小型可达性探测；
  仍可达的设备继续使用上一份完整目录播放，并报告同步错误。实际断连才离线。
- Classic 导入优先复用唯一的显式整文件剧集；不覆盖同来源的冲突身份。
  显式绑定遇到 Classic 占用时，仅在文件及时间范围集合完全相同的情况下
  复用归属并记审计，其余仍维持原子拒绝。

## 不应误判的状态

`presence.at` 表示前后台状态发生变化的时间，不是心跳计时。
文件 HTTP 代理为接收端按需启动；`not_started` 和配置端口 0 分别表示尚未
请求地址、自动分配端口。Mesh 合并 ID 是当前节点的投影 ID，跨设备写入
必须通过 `media.management.targets` 取得拥有者的原始实体 ID。

## 验证

已通过：大于 1 MiB 的中文演职员目录往返、旧分页兼容、版本变化拒绝部分
目录、continuation 设备隔离/过期/完整性检查、真实双向 TLS 大响应且原操作
只执行一次、真实 Mesh Range 与定位、Classic 复用与既有撤销/冲突回归。
真实 TLS 回归另覆盖：目录报错或数据损坏时旧目录仍可读、恢复后清除错误、
来源退出后才变为离线，以及分页期间进度版本变化仍完成同一份目录。
Mac/Windows 安装后的真实目录同步与播放验收另外记录，不能由单元测试代替。

## 来源详情显示的独立问题

`mergedMetadata` 的综合字段会从历史快照补齐缺项，但 `sources` 原来只保留
同一对象和语言的最新一条。图片更新的稀疏快照因时间更新，遮住旧快照里的
TMDB 演职员；库中有数据仍可能在详情页显示尚未获取。来源详情现在也按字段
补齐缺项，并以 `fieldProvenance` 保留每个字段的实际快照与时间。已有手交
快照的历史淘汰规则保持，单测覆盖新的图片快照不遮住演员及来源追踪。
