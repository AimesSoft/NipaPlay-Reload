# 数据与恢复

预览版可能改变数据格式。升级、恢复或试验整理前，先退出应用并备份；确认备份可读后再操作。不要把同一数据目录同时交给两个运行中的实例。

## 两种备份范围

应用的 Classic `.npb` 全量备份可选设置、媒体库、观看历史、剧集匹配和账号类别；恢复会合并或改写所选数据。它不包含 `next.db`、Next 图片及导入的弹幕文件，也不是 Next 对话和个人 harness 的完整备份。账号导出保留便携引用，不导出登录秘密；恢复只能使用本机已有的凭据引用，必要时重新登录。`.nph` 是观看历史备份，范围更窄。

Next GUI 的数据根目录是应用存储目录下的 `next/`，其中包括 `next.db`、配置和部分资源；实际应用存储位置因平台、沙盒和设置而异。DSH 高级配置页面显示 `dsh-config.json` 的绝对路径，其父目录即 Next 数据根目录。梨花的文件夹可能另有位置，可在设置中的「梨花的文件夹」核对；媒体原文件也可能在应用目录之外。备份时将这些需要保留的目录分别保存，包含 SQLite 的伴随文件；关闭应用后复制，避免取得不一致快照。

凭据保存在系统凭据保险库，而非 `next.db`，复制目录不能保证模型密钥、登录或 Mesh 私钥可迁移。恢复到另一台设备时可能需要重新登录、配置密钥和重新加入组网；不要将同一个设备身份复制到同时在线的多台设备。Headless 使用独立数据目录，详见 [Headless 备份说明](HEADLESS.md)。

## 同机恢复

先关闭应用，把当前目录另存一份，再按同一设备的备份恢复对应目录及另存的梨花文件夹；启动后核对媒体文件路径、观看进度、对话和凭据。Classic `.npb` 则先预览并选择要恢复的类别，检查实际结果，部分服务需要重启。跨平台或跨版本目录恢复尚无完整迁移保证；系统沙盒与目录授权可能需要重新授予。无法确认时保留原件和备份，附版本与平台反馈，不要反复覆盖唯一副本。

## 迁移到另一台设备

不要将旧设备的整个 `next/` 目录直接覆盖到新设备，尤其不要复制 Mesh 身份使两台设备同时在线。先在新设备完成安装、登录和组网；凭据与目录授权按新设备重新配置。`.npb` 仅恢复其支持的 Classic 类别，Next 数据和个人 harness 的跨机迁移尚无完整验证流程；保留旧设备原件和备份，核对路径与数据后再处理。
