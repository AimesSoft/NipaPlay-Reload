# 架构复审：清除“上一个时代的软件思维”（2026-10-11）

> 依据用户提出的原则：给 Agent 工具，而不是替 Agent 编排流程；目标是为 Agent 提供方便，而不是限制 Agent。原则正文见 `DESIGN.md` §2.3。

## 判断标准

- **工具**：是否是可组合、支持批量、语义清楚的能力原语？Agent 能否用很少的调用、自然地组合出目标？
- **代码**：是否只负责不变量（数据一致性、来源记录、幂等、权限与 Effect）和基础设施（没有 Agent 也必须运转的事）？
- **说明**：`AGENTS.md` 与工具说明是否只陈述事实、目标、边界，而不规定调用顺序？

## 复审结论

| 部分 | 结论 | 处理 |
|---|---|---|
| 识别流水线（文件名解析、候选、Decision 节点、证据、重新判断、Release 级联） | 旧思维 | 重构为能力原语：目录列表、批量哈希匹配、元数据搜索与查询、批量绑定（进行中） |
| `AGENTS.md`（意图 → 调用顺序表、步骤说明） | 旧思维 | 已重写为事实、目标、边界 |
| MCP `initialize` 中的说明 | 旧思维（在教步骤） | 精简为事实陈述 |
| 来源契约（`DanmakuSource` / `MetadataProvider` / `ReleaseSource` 固化“搜索 → 定位 → 获取”接口） | 隐蔽的旧思维 | **契约只约束数据，不约束流程**：宿主要消费的数据格式（标准弹幕条目、元数据快照、发布候选）是契约；一个来源就是一组 Agent 可直接调用的 Action，如何搜索、定位由它自己决定。新来源（包括 Agent 生成的）不必套进预设接口 |
| 弹幕对齐（任务产出候选 → 二选一 apply / keep） | 带决策协议的味道 | 改为提供对齐分析数据，Agent 判断后直接设置偏移 |
| `NeedsDecision` | 需要降级 | 保留为“把歧义以数据返回”与 GUI 一点即执行的按钮；不得用来驱动流程。逐一排查现有用法 |
| 工具规模与形态（58 个工具，多为一对一的 getter） | 新问题 | 收敛为少量更强的通用工具（`settings.*` 是范例）；考虑面向有文档说明的状态的只读查询工具；提供工具发现，避免工具列表无限膨胀 |
| 任务引擎 | 保留 | 它是基础设施，负责执行。任务内部不内置“何时请示 Agent”的判断流程；需要判断的场景，以事件或数据告知 Agent |
| 设置注册表、凭据保险库、Mesh、Effect 与审批 | 保留 | 它们是原语，或在守安全不变量与权限边界 |
| `docs/ARCHITECTURE_DECOUPLING_TODO.md`（全量 SDUI 路线图） | 废止 | 协议优先、ViewModel 优先的旧思路；在“Agent 编排 UI + 共用 Harness”的架构下无需全量 SDUI |

## 执行顺序

1. 识别重构（进行中）。
2. `AGENTS.md` 重写（已完成）。
3. Agent 易用性整体评审（sol，只读，出方案）：覆盖全部工具，以及 `NeedsDecision` 用法、弹幕对齐、MCP 说明、来源契约。主控定稿后分批实施。
4. 按评审结论依次改造弹幕与其他领域。

## 定稿（2026-10-11，依据 `research/AGENT_ERGONOMICS.md`）

整体采纳评审方案，补充与排期如下：

- `state.query` 即“只读通用出口”。通用写出口暂不提供：现有原语与 `settings.*` 已经覆盖写操作；将来若需要，必须按 read / write / destructive 分级，并由宿主检查目标 Action 的真实 Effect，不得出现自动批准的万能调用器。
- `media.metadata.override` 不再限定只有 GUI 能调用：Agent 可以编辑，宿主如实记录 actor 与 origin；持久覆盖与普通修正用数据字段区分。
- 覆盖率基线改为同时维护：能力覆盖、主要 Action 契约、兼容映射（旧 Action → 新入口）。减少 Action 数量与保持能力覆盖可以同时成立。
- 排期：
  - 第 2、3 批立即开始；
  - 第 1、4 批在识别重构合并后开始；
  - 第 5 批在第 4 批之后；
  - 第 6–8 批依次推进。
