# 媒体模型：文件、身份与展示

Next 保存文件、作品层级、来源身份与展示资料等不同事实。一个本地视频能被打开，不代表它已经被确认为某部作品的某一集。Agent 或用户核实候选并明确提交判断；宿主记录事实、执行变更和提供回执。

## 作品与文件

- **work** 表示作品；**release** 表示该作品的版本或季等发行层级；**episode** 表示其中的一集或相应内容。层级是本地目录实体，不自动等同于某一外部站点的编号。
- **file** 是被索引的媒体文件；location 说明它在何处、由哪台设备持有和最近的可用事实。一个文件可关联多个 episode，一集也可有多个文件位置。关系还可保存起止时间和顺序；同一文件中的不同区间不应因为名称相同而折叠。
- 扫描、下载完成和探测登记文件、路径、长度、哈希或技术事实。未知时长、尚未索引的文件 ID 和不可达位置可以是未知，不能当作错误作品或自动绑定的证据。头部哈希和外部搜索返回的是候选，文件名也是数据。
- 本地自编目录可用稳定本地 ID 建立作品、发行和剧集，不需要伪造外部站点身份。移除目录实体与删除硬盘文件不同：领域操作可以保留 tombstone、前像和观看进度，具体撤回条件以实际契约为准。

## 身份、资料和图片

外部 ref 带 provider、对象类型、外部 ID 和 scope。站点的对象 ID、显示集数、本地 entityId 与设备路径属于不同命名空间。已接受、候选、拒绝和撤销的身份具有不同含义；同名或同集号不能自动当成同一实体。绑定记录来源、理由和审计事实；当冲突或证据不足时应保留不确定性。

来源快照保留各提供方的字段和来源事实；展示资料可汇总来源，也可有用户或 Agent 的覆盖。刷新来源不必改变身份，清除覆盖也不等于删除来源或磁盘文件。图片、文字覆盖与原始来源快照有各自生命周期。是否有完整标题、简介、海报或剧集截图，应查询实际展示事实，不能仅从来源已绑定推断。

## Classic、投影与合并

Classic 与 Next 共享明确约定的数据，例如观看记录和续播进度；Next 的识别判断与 Classic 的自动识别隔离。Next 启动、下载完成或扫描不隐式导入 Classic 身份。旧身份只有通过显式导入进入 Next；Next 已提交绑定可由 outbox 投影给 Classic，投影回执和原数据库提交是不同事实。

跨设备合并目录是供接收端展示与搜索的投影。显示的合并 workId 不一定是源设备写入时需要的原始 ID；执行身份或合并变更前，应解析到拥有者设备的原始 work、episode 和 file ID。完整作品合并要明确 release/episode 对应、检查冲突并预览；绑定变更只是关系修改。合并后的旧 ID 可以有别名，写入应使用当前目标要求的 ID。

常见误解：**目录里显示海报**不证明文件可播放；**资料来源已接受**不证明字幕或弹幕已取得；**扫描成功**不证明识别正确；**投影尚未更新**不证明提交回滚。通过领域读取、任务与回执分别核验。
