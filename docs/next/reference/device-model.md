# 设备模型：宿主、Mesh 和数据归属

每台设备有自己的进程、配置、库、文件权限和实际能力目录。版本相同也不代表已配置相同来源、凭据、网络、播放器或 Agent。查询远端时应以接收设备的目录和状态为准；安装或实现存在不证明外部服务当前可达。

## 宿主角色

- **桌面 GUI** 运行 Next 的界面、播放器和本机能力；启用 Next 时接入 Agent 端点与 Mesh。Classic 与 Next 分别拥有界面和播放会话；切换时关闭当前会话并保存进度，不自动接续另一边的播放。
- **Headless** 是无界面宿主，组合媒体、任务、Mesh 和可配置的对话宿主。没有 GUI 窗口或本地播放器就不能推断桌面操作可用；它对部分能力有独立实现或过滤，根目录配置与桌面也不同。
- **iOS body-only** 提供界面、播放器、能力层和 Mesh，不启动本地 Agent 端点或会话宿主；可选择其他设备上的 Agent。该角色过滤窗口、程序、对话、Agent 和记忆等一组本机能力。具体设备和动作仍以运行目录为准。

## 来源和投影

Mesh 对同账号设备建立认证通信；在线、身份、可路由、目标能力注册及权限分别决定一次操作能否执行。设备名可能重名，设备 ID 用于明确目标。远端路径属于拥有者，不是调用端路径；临时回环 URL 属于接收端进程，不能保存为永久文件位置。

合并媒体库是接收端的目录投影：可保留设备离线前的旧观察。设备可达性、目录新鲜度、图片获取与实际文件读取是不同事实；旧目录存在不证明文件当前可读。写入目标的库时使用目标自己的原始实体 ID 和前置条件，不假定跨设备事务原子。

Next 的首页书架和媒体库分类排列属于当前设备的展示数据；对目标设备调用写入的是目标设备的排列，不会因此改写远程来源服务器上的分类或媒体文件。远程来源本身的目录、路径和账号则属于来源服务及其配置，须按来源状态理解。

## 状态与边界

`app.instance` 识别所连接进程，`app.capabilities` 描述宿主提供的动作和声明前置，`mesh.devices` 描述设备和近期观察。目录中的 `available` 不等于一次实时联网成功；没有观察时应保留 unknown。跨设备写入或删除依据用户意图和目标操作确认，Mesh 认证本身不是对每项破坏性操作的授权。

常见误解：**远端列表可见**不等于当前在线；**相同作品标题**不等于同一源设备 ID；**缓存海报存在**不证明源文件可播放；**能远程调用一个 Action**不证明所有动作都可远程调用。
