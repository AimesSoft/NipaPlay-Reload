# 配置梨花

梨花由三部分组成：

- **NipaPlay**：提供各种能力（查片库、下载、播放、改资料……），以工具的形式交给梨花；
- **运行器**：负责和模型对话、把模型选中的工具交给 NipaPlay 执行、管理上下文。默认是 DeepSeek Harness（DSH），也可以用 Codex；
- **模型**：由你选择的服务商提供，负责理解请求、决定调用哪些工具。

所以要让梨花工作，需要准备好运行环境，再填一个**支持工具调用**的模型。本篇在桌面（macOS、Windows、Linux）上进行；iPhone/iPad 不在本机运行梨花，做法见[多台设备](../use/devices.md)。

## 推荐配置

首推下面两个模型。它们工具调用稳定、价格低、支持图片，可以直接照填：

| | DeepSeek V4.1 Flash（1017） | GLM-5.3 Flash |
|---|---|---|
| 设置页模板 | DeepSeek | 智谱 |
| 地址 | `https://api.deepseek.com` | `https://open.bigmodel.cn/api/paas/v4` |
| 模型（API 模型 ID） | `deepseek-flash` | `glm-5.3-flash` |
| 接口 | **Responses** | Chat Completions |
| 图片输入 | 支持 | 支持 |
| API key | [DeepSeek 开放平台](https://platform.deepseek.com/) 创建 | [智谱开放平台](https://open.bigmodel.cn/) 创建 |

**显示名称和 API 模型 ID 不是一回事。** "DeepSeek V4.1 Flash 1017"是模型的发布名称；直连 DeepSeek 官方 API 时，「模型」一栏要填 API 模型 ID `deepseek-flash`，目前由 V4.1 Flash 1017 提供服务。通过 OpenRouter 等中转服务时，模型 ID 由中转方规定，例如 `deepseek/deepseek-v4.1-flash`；请以中转方文档为准，不要把发布名称直接填进去。

**接口类型要和地址匹配。**

- DeepSeek 官方 API 在同一个地址上同时支持 Responses 和 Chat Completions，推荐选 Responses。
- 智谱的 Chat Completions 地址是 `…/api/paas/v4`，Responses 地址是 `…/api/v1`。官方文档为 GLM-5.3 Flash 写明的是 Chat Completions，所以这里推荐 Chat Completions。

其他服务商也可以用：只要提供 OpenAI 兼容的 Responses 或 Chat Completions 接口，并且模型支持函数调用（function calling）即可。不支持工具调用的模型只能聊天，做不了任何事。

## 第一步：准备运行环境

1. 打开「设置」→「梨花」（或点顶栏的「设置梨花」）。
2. 「运行器」保持 **DeepSeek Harness**。
3. 「运行环境」显示「未下载」时点「下载」。NipaPlay 会下载固定版本的 Node.js 和 DSH，依次显示下载中、校验中、正在安装，完成后显示「已就绪」。
   - 下载失败显示「没能下载」，可点「重试」；网络受限时可在「运行环境选项」里换镜像，或用「使用指定的运行环境」指向已有的安装。
   - 显示「这个平台暂时没有」，说明没有为这个系统和架构预置运行环境。可以在另一台受支持的桌面设备上运行梨花，再通过[组网](../use/devices.md)使用她。

## 第二步：填写模型

1. 在模型区域点模板按钮（「DeepSeek」或「智谱」），它会填好提供方、地址、模型、接口和思考强度，以及该服务商需要的兼容开关。
2. 按上面的推荐表核对。**选 DeepSeek 时，把「接口」改为 Responses。**
3. 在「API key」填入你在服务商平台创建的密钥。密钥存在系统的凭据保险库里，不写进配置文件；保存后输入框显示「已保存」。
4. 「思考」控制模型的推理强度（关、低、中、高）。强度越高越慢、越贵，一般保持模板的默认值。
5. 点「保存」，再点「测试连接」。

## 第三步：看懂"测试连接"

「测试连接」向你填的地址发一次很小的真实请求，请求里声明一个无害的测试工具 `nipaplay_connection_check`，不会执行任何操作。

- **成功**：显示「可以用 · 数百 ms」。
- **失败**：直接显示原因，例如「密钥无效或没有权限」「账户余额不足或额度已用完」「模型名不存在」「端点不支持 Responses 接口」「此模型不支持工具调用」「未通过工具调用检查」「连不上服务器」「服务器响应超时」。

两种接口检查的严格程度不同：

| 接口 | 检查方式 | "可以用"能说明什么 |
|---|---|---|
| Responses | 要求模型调用测试工具（服务商不接受指定工具时改为让模型自选，仍要求它真的调用） | 地址、密钥、模型都正确，**且模型确实发出了工具调用** |
| Chat Completions | 只声明测试工具，不要求调用 | 地址、密钥、模型都正确，且服务端接受工具声明；**不能证明模型会在真实任务里调用工具** |

两种检查都**不测试图片能力**，也不代表每个任务都会成功。所以还要做第四步。

## 第四步：在对话里实际验证

打开对话（顶栏右侧），依次发送：

1. **验证工具调用**：「看看现在 NipaPlay 的情况，播放器在放什么？」
   - 正常时，回答上方会出现「看 NipaPlay 的情况」「查状态」之类的工作步骤，可以展开查看工具输出，然后她根据结果回答。
   - 如果只有一段文字、没有任何步骤，说明模型没有调用工具，常见原因见[常见问题](../help/faq.md#连接测试成功但梨花不调用工具)。
2. **验证图片**：粘贴或拖入一张截图，问「图里是什么？」。
   - 能描述内容，说明图片输入可用。
   - 服务商不支持图片时，会在对话里报出服务商返回的错误。这时可以继续用文字对话，只是不能让她看图。

验证通过后，就可以开始[第一次使用](first-day.md)了。

## 费用与隐私

- 模型按服务商的价格计费。一个任务往往包含多轮工具调用，比普通聊天消耗更多 token。
- 任务所需的对话、工具结果、文件名、路径以及你发送的附件，会发给模型服务商，适用对方的数据政策。不要让她处理你不愿分享的内容。
- API key 是个人凭据，不要放进截图、日志或反馈。

## 使用 Codex 作为运行器

「运行器」也可以选 Codex，适合已经在用 Codex 的开发者：

- 可以使用「系统里的 Codex」，或在 NipaPlay 里设置路径；
- 可以用「导入 Codex 配置」把电脑上 Codex 的模型配置导入进来；
- Codex 只支持 Responses 接口。

上下文预算、压缩和插件等更多配置见 [DSH 高级配置](../advanced/dsh-config.md)。
