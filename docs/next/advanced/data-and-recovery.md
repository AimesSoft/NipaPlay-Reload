# 数据与恢复

预览版可能改变数据格式。升级、恢复或尝试整理之前，先退出应用并备份，确认备份可以读取后再操作。不要让两个运行中的实例同时使用同一个数据目录。

## 数据在哪里

| 内容 | 位置 | 说明 |
|---|---|---|
| Next 数据根目录 | 应用存储目录下的 `next/` | 包括 `next.db`（片库、作品身份与资料、任务、书架和布局等）、`dsh-config.json`、图片和导入的弹幕。实际位置因平台、沙盒和设置而不同；[DSH 高级配置](dsh-config.md)页面显示 `dsh-config.json` 的绝对路径，它的父目录就是数据根目录 |
| 个人 harness | 默认 `~/nipaplay-harness`（Windows 为 `%USERPROFILE%\nipaplay-harness`） | 梨花的指令、记忆、工具和脚本，是一个 Git 仓库。实际位置看「设置」→「梨花」→「文件夹」 |
| 本机连接凭据 | macOS/Linux `~/.config/nipaplay/endpoint.json`，Windows `%APPDATA%\NipaPlay\endpoint.json` | `nipa` 命令行连接本机用，每次启动重新生成，不需要备份，也不要分享 |
| 凭据 | 系统凭据保险库（钥匙串、Windows 凭据管理器、Secret Service） | 模型密钥、账号登录、Mesh 私钥。不在 `next.db` 里 |
| 媒体文件 | 你添加的文件夹、下载目录 | 在应用目录之外，自己另行备份 |

[Linux 无界面版](headless.md)使用独立的数据目录，不和桌面版共用。

## 两种备份

**复制目录**：关闭应用后，复制 Next 数据根目录和个人 harness。SQLite 的伴随文件（`next.db-wal`、`next.db-shm`）要一起复制；应用运行时复制，可能得到不一致的快照。

**Classic 的 `.npb` 备份**：可以选择设置、媒体库、观看历史、剧集匹配和账号几类数据，恢复时合并或改写所选数据。它**不包含** `next.db`、Next 的图片和导入的弹幕文件，也不包含对话和个人 harness，不能代替目录备份。账号导出只保留可携带的引用，不导出登录秘密；恢复时只能用本机已有的凭据，必要时重新登录。`.nph` 只备份观看历史，范围更窄。

复制目录不能保证模型密钥、登录状态和 Mesh 私钥可以迁移，因为它们在系统凭据保险库里。

## 在同一台设备上恢复

1. 关闭应用，把当前的数据目录另存一份。
2. 用备份替换数据根目录和个人 harness。
3. 启动，核对媒体文件路径、观看进度、对话和凭据。

恢复 `.npb` 时，先预览并选择要恢复的类别，恢复后检查实际结果，部分服务需要重启。

跨平台或跨版本恢复目录目前没有完整的迁移保证，系统沙盒和目录授权可能需要重新授予。拿不准时保留原件和备份，带上版本和平台信息反馈，不要反复覆盖唯一的副本。

## 迁移到另一台设备

- 不要把旧设备的整个 `next/` 目录直接覆盖到新设备，尤其不要复制设备身份，让两台设备同时以同一身份在线。
- 先在新设备上安装、登录和加入组网；凭据和目录授权在新设备上重新配置。
- 个人 harness 是 Git 仓库，可以推到你自己的远端再在新设备上克隆，记忆和工具随之迁移。
- `.npb` 只恢复它支持的 Classic 类别。Next 数据跨设备迁移目前没有验证过的完整流程；保留旧设备的原件和备份，核对路径和数据后再处理。

如果只是想在新设备上看旧设备的片库，不必迁移，[加入组网](../use/devices.md)即可。
