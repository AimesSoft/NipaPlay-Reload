# 梨花的商店

商店给梨花装两类扩展：

- **技能**：一组说明加脚本，教梨花新的本事，比如更多 BT 来源、弹幕工具。梨花用命令行运行这些脚本，查到的结果仍按平常的规则处理：推荐不等于下载，订阅要你明确提出。
- **插件**：DeepSeek Harness 的 npm 插件，例如给梨花接入别处的模型。插件只在 DSH 运行环境下加载，用 Codex 时不生效。

在「设置 › 梨花 › 扩展」中查看和安装。确认安装时，装的是你看过说明的那个版本；列表恰好在这期间更新了，会请你重新确认。梨花替你装官方条目时也要先把说明告诉你，并指定那个版本。安装、卸载、开关以后，点「重启梨花」或等她下次启动时生效；重启会结束正在进行的回合。

## 官方列表

官方列表在 [AimesSoft/rika_plugins](https://github.com/AimesSoft/rika_plugins)，每个条目有说明页，列表里的每个文件都记录了 SHA-256。NipaPlay 先从 GitHub 读取，读不到时改用 jsDelivr 上的同一份副本；文件与列表不符就不安装，所以副本只可能旧，不可能被改动。列表最多每 10 分钟重读一次，「刷新」立即重读。

列表里的插件都经过代码审查，并锁定到具体版本。有些插件会带「安装前须知」，例如使用第三方订阅可能违反服务商条款、账号有被限制的风险，安装前会先让你确认。

## 任意 npm 包

也可以输入 npm 包名（`name` 或 `name@version`）安装没有收进官方列表的包。这些包**没有经过审核**，界面标为「未审核」：

- 插件在梨花的运行环境里运行，技能的脚本由梨花运行。它们能读写你的账户能访问的文件、连接任意网络地址，也能看到交给它的数据。只安装你信任、知道来历的包。
- 商店不运行包的安装脚本。需要安装脚本的包、依赖不在梨花运行环境里的插件、`cordis.patch.yml` 会改动其他插件的插件，都不会安装。
- 带 `SKILL.md` 的包装成技能，DSH 插件装成插件，其他包不能安装。
- 下载按 npm 给出的完整性校验值核对。使用的 npm 地址与 [DSH 运行环境下载](dsh-config.md)相同：设置了 npm 镜像就用镜像，否则先用 npm 官方地址，再用 npmmirror。

只有你本人在这台设备的界面里能安装 npm 包；梨花可以从官方列表安装你要的条目，但不能自己装未审核的包，也不能自己重启，经 Mesh 从其他设备也不行。无界面版在主机的终端里运行 `nipaplay-headless --store-install-npm 包名 --data 数据目录`，按提示输入包名确认，装好后重启服务；梨花的工具调用没有终端，不能这样替你装。在 DeepSeek Harness 下，插件目录和安装记录对梨花的工具是受保护的路径，点名它们的调用会被拒绝（Codex 下没有这层拦截，但插件也只在 DSH 下加载）。梨花和你以同一个系统用户运行，这些是防止她顺手替你装的步骤，不是隔离；用别的方式拼出路径仍能写入。

## 存放位置

扩展在 Next 数据目录的 `store/` 下（位置见[数据与恢复](data-and-recovery.md)）：`skills/<id>/` 是技能文件，`plugins/<id>/` 是插件包，`installed.json` 记录装了什么、是否启用。插件需要的 DSH 自带的包，在梨花启动时链接到当时的运行环境，运行环境更新后不用重装。

插件写在 DSH 自己数据里的设置和登录，卸载插件时不会删除。无界面版用 `nipa call store.list`、`store.install` 等动作管理，动作说明见 [Action 参考](../development/ACTION_REFERENCE.md)。

## 开发

设置环境变量 `NIPAPLAY_STORE_INDEX` 为商店仓库的本地目录（或其中的 `index.json`），NipaPlay 就改读这份列表，方便发布前试装。条目格式、审核规则和生成列表的工具见商店仓库的 README。
