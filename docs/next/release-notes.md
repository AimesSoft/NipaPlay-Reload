# NipaPlay Next · Developer Preview

这是 NipaPlay Next 的第五个开发者预览（Alpha 5）。Next 重新组织了媒体库、播放器和个人助手之间的关系：你通过对话表达想做的事，梨花查询信息、选择工具并执行，结果呈现在书架、作品资料、播放器和弹幕里。

Alpha 5 为手机重新设计界面和播放器，新增 Apple TV 版本，语音输入可以使用自配的云端识别服务；鸿蒙设备的 Next 适配也已合入。多段对话可以同时进行，各设备共享同一份对话列表；梨花可以追番、追剧，按她写的规则自动下载新集；页面静止时不再持续绘制。Next 不再接入 Jellyfin、Emby 等外部媒体服务器，这些服务请在 Classic 中使用。下面介绍本次更新与 Next 的主要能力。

本次预览由 **AimesSoft** 发布，面向开发者、Agent 系统爱好者，以及愿意一起探索这种使用方式的用户。

> [!CAUTION]
> **⚠️ 高风险实验性软件 · 仅供具备相关技术经验的用户测试**
>
> **NipaPlay Next 是具有完整用户级系统权限的 AI Agent 实验，而非面向普通用户的稳定版播放器。** 本次发布仅面向开发者、Agent 系统研究者及充分了解相关风险的技术爱好者。如果你不熟悉系统权限、Agent 行为及数据恢复，请继续使用 NipaPlay Classic。
>
> **Agent 具有广泛的系统操作能力。** 梨花可以在应用进程及当前用户拥有的权限范围内读写、覆盖和删除文件，运行程序、联网，并使用可访问的账号和登录状态。它的操作范围可以超出 NipaPlay 媒体库；不要将它视为只会回答问题的聊天窗口，也不要假定所有操作都会再次弹窗确认。
>
> **风险同样延伸到 Mesh 和内网设备。** 加入组网意味着信任同账号认证设备访问本机开放的能力和应用进程可访问的文件；启用远程程序运行后，其他设备上的 Agent 还可以在本机执行程序。处于同一局域网并不意味着安全，设备认证也不能防止已经受信任的 Agent 作出错误操作。
>
> **模型行为不可完全预测，错误操作可能造成不可逆的损失。** 模型误判、软件缺陷，以及网页、文件名、字幕等外部内容中的恶意指令，都可能引发数据丢失、隐私或凭据泄露、账号操作和额外费用。关闭 Next、切换回 Classic 或卸载应用，都不能自动撤销 Agent 已经执行的操作。
>
> **请仅在可承受损失的测试环境中使用。** 强烈建议使用隔离的测试设备、独立系统账号和可丢弃的数据副本，保留离线备份，只加入可信设备。**不要在存放唯一重要数据的主力电脑、工作设备或关键业务环境中直接试用。** 当前 Next 尚未提供完整的产品内备份与恢复能力。
>
> **注意模型服务的数据传输。** 模型服务会接收任务所需的对话与工具结果，其中可能包含文件内容、路径或其他敏感信息。请自行选择可信的服务商，了解其数据政策及可能产生的 API 费用。
>
> **如果你无法独立处理系统故障、检查 Agent 操作或恢复重要数据，请勿启用本次 Alpha 实验。**


## Alpha 5 更新了什么

### 对话

- **多段对话同时进行**：一段对话正在进行时，在另一段里说的话立即开始，不再排队。
- **所有设备共享一份对话列表**：手机、平板和电视使用另一台设备上的梨花时，可以看到并接着使用那台设备上的全部对话；在手机上开始的对话同样出现在那台设备上。回复、提问和标题变化实时同步。

### 在追与自动下载

- **请梨花追番、追剧**：说明要追的作品，梨花确认作品身份、选择来源（蜜柑计划和其他 RSS、Jackett、Prowlarr、PT 站 RSS），写下筛选规则，先给你看一次候选，再建立订阅和定时巡查。
- **普通检查不唤醒梨花**：巡查程序定时按她写的规则查找新集，命中后直接下载，完成后绑定到对应作品和集数。规则要求询问、候选冲突或连续出错时才请她处理。
- **「动态 → 在追」**：列出各设备上的订阅，显示梨花写的说明、最近一次检查、最近下载的集数和错误，可以暂停、继续或移除。
- **密钥保险库**：Jackett、Prowlarr 的 API Key 和 PT 站 passkey 由梨花存入凭据保险库，不进入审计、数据库、回执和 harness Git。
- 订阅在运行梨花的设备（电脑或无界面宿主）上执行；手机、平板和电视可以查看和管理。详见[订阅与自动下载](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/use/subscriptions.md)。

### 媒体来源

- **Next 不再接入 Jellyfin、Emby、弹弹play 远程访问和 NipaPlay 共享。** 这些服务自己管理作品身份与资料，服务器常属于他人；Next 由梨花读取文件内容匹配作品身份，对这类来源会产生大量流量。需要使用它们时请回到 Classic。SMB 和 WebDAV 继续可用。
- 升级后，Next 数据库中来自这四类来源的作品、文件位置、缓存和未结束的同步任务会被清理；梨花为这些作品建立的 TMDB、Bangumi、弹弹play 身份保留。Classic 的来源配置、凭据、观看记录和续播进度不受影响。

### 性能与耗电

- **页面静止时不再绘制**：首页背景推进、主视觉弹幕、梨花头像光环、后台任务图标、进度条流光等动效只在出现或状态变化时播放几次，随后静止。iPad 真机测量中，各页面静止时的绘制由每秒 60 帧降至约 1–2 帧。
- **推送代替轮询**：界面不再每秒多次查询数据库；组网目录由持有方在变化时通知，不再每 5 秒刷新；网络接口变化由系统通知，下载观察只在有任务时运行。
- **手机上不再每帧重绘模糊**：柔化的海报和背景改用小尺寸解码，玻璃面板不再实时模糊背后的内容，图上文字改用清晰投影。滚动时的渲染开销约减半。
- 文本框光标改为直接闪烁；手机和平板打开对话时不再自动弹出键盘。

### 手机与平板界面

- **底栏**：底栏上一行是梨花的入口，显示她正在做的事，点击打开对话，点麦克风直接开始听写；下一行是首页、发现、媒体库、动态和搜索。顶栏只保留后台任务和菜单。
- **首页与作品详情**：背景图铺满上半屏，主按钮占满一行；剧集改为竖排列表，显示剧照、观看进度和弹幕热度。媒体库一行三张海报。
- **横竖屏播放**：视频随手机旋转。竖屏时，底部玻璃胶囊放置播放、时间、带弹幕热度的进度条和全屏，弹幕、字幕、剧集、更多排在胶囊上方；横屏时这些控件并入胶囊，菜单从右侧弹出。
- **iPad 与手机一致**：分区、搜索和梨花的入口都在屏幕底部。
- **系统控件**：iOS 26 起，底栏的分区与搜索使用系统标签栏，右上角「…」使用系统菜单。
- **键盘**：键盘弹出时，对话输入框、设置项和搜索结果留在键盘上方；在对话中下滑或点空白处收起键盘。
- 对话面板延伸到屏幕底边，输入框位于 Home 指示条上方；竖屏播放时打开对话，视频移到面板上方。
- 竖屏播放时，字幕和弹幕限定在画面范围内。
- 对话标题显示运行梨花的设备，打开对话时查询该设备是否可用。
- 发现页「新番日历」「排行榜」的标签在手机上可横向滚动；设置项的标题在手机上不再被输入框截断。

### Apple TV

- **新增 Apple TV 版 Next**：电视运行 Next 界面、播放器和组网，对话由同账号其他设备上的梨花处理。梨花可以在电视上播放、调整设置和截取画面。
- **十英尺界面**：电视上的页面整体放大 1.6 倍，文字、卡片和控件比例不变。同一时间只有一个焦点：按钮聚焦时翻为纸色，卡片和提问栏聚焦时放大并带光环。首页主视觉占满首屏。
- **遥控器播放**：观看时左右键快退、快进 10 秒，确认键播放或暂停，下键唤出控件；Menu 键先收起控件，再按离开视频。
- 附件提供需自行签名侧载的 tvOS IPA。TestFlight 测试构建与 iPhone 版同属一个 App，开放测试的方式以发行页公告为准。

### 鸿蒙

- 鸿蒙设备可以开启 Next，运行界面、播放器和组网，使用其他设备上的梨花；内置 SQLite，并迁移原有数据库位置。播放时切换横屏，系统返回手势先退出播放。适配由 [@aozaoz112233](https://github.com/aozaoz112233) 贡献（[#1104](https://github.com/AimesSoft/NipaPlay-Reload/pull/1104)）。
- 附件提供已签名的鸿蒙 HAP（arm64）。

### 语音输入

- **自配云端识别**：在「设置 → 实验室 → 语音识别服务」选择 Azure 或百炼，填写自己的地址和 API Key。云端模式将录音直接发送给所选服务商，可能产生费用；本机离线模型继续可用。详见[梨花](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/use/nipa.md#语音输入实验室)。
- macOS 听写改用普通麦克风输入，避开系统语音处理在仅录音时出现的失败。

### 播放、启动与组网

- 播放器「播放信息」显示 Erika 实际运行的超分和解码器状态。
- 目录、字幕和弹幕索引或观看记录初始化失败时，梨花仍可启动和对话；首页提供「重试目录」，梨花可通过 `diagnostics.startup` 查询失败位置。
- 无法读取的媒体文件不再阻塞梨花启动（[#1100](https://github.com/AimesSoft/NipaPlay-Reload/pull/1100)，[@aozaoz112233](https://github.com/aozaoz112233)）。
- 组网监听遇到临时错误后继续接受连接；后台目录加载图片时使用应用的代理和证书设置；macOS 提高应用的文件描述符上限。

## 我们希望探索什么

整理媒体往往是一连串具体判断：文件是哪一集、几个版本该选哪个、资料应该如何补齐、哪台设备能提供视频、怎样把片库摆成自己喜欢的样子。我们希望用户能够直接表达目标，让 Agent 根据当下的文件、来源和设备状态完成这些工作。

这也是 Next 的分工：**梨花负责理解和判断，NipaPlay 负责具体执行、保存数据和报告结果。** 文件识别工具提供候选，明确的匹配操作建立作品归属；下载、播放和后台任务有可查询的状态，资料修改保留来源，支持的写入提供预览与回执。图形界面承载观看体验，也让对话中的操作有看得见的结果。

每个人还拥有自己的 **Git harness**——一个保存工具、脚本、偏好和操作经验的个人仓库。梨花可以在实际任务中维护它，复用已有工具、补充脚本，记录适合你的工作方式。经验随着使用积累，你也可以打开文件查看、修改和管理 Git 历史。

## Next 的功能（Alpha 1 起）

### 独立的 Next 界面与播放器

- 新增首页、媒体库、作品详情、对话和播放界面，将观看内容与梨花的工作结果放在同一套体验中。
- 首页呈现继续观看、最近播放和自定义书架；作品详情汇集剧集、资料、图片和播放来源。
- 提供独立播放会话与内核控制，支持续播、定位、音轨和字幕轨道选择，以及本地和 Mesh 远端媒体播放。
- 保留 Classic。可在设置中切换两套界面，部分设置、观看记录与续播进度继续共用；切换时保存进度并关闭当前播放会话。

### 梨花对话与个人工作环境

- 接入 DeepSeek Harness（DSH）和 Codex 会话运行器。桌面设置提供 DSH 运行环境下载，以及模型服务商、接口地址、模型和 API key 配置。
- 对话支持流式输出、图片附件、工作过程查看和作品、剧集、任务等结果卡片。
- 完整历史采用渐进加载，向上翻阅可以继续读取早期回合；DSH 提供上下文压缩，个人记忆另行保存在可查看和编辑的文件中。
- 开放 DSH 高级配置，包括上下文预算、压缩和插件设置，并提供配置文件编辑入口。
- 个人 harness 保存工具、记忆和事件脚本；官方种子更新会保留个人修改，遇到合并冲突时报告状态。可通过 hooks 和定时程序安排后续工作。

### 媒体身份、资料与整理

- 建立作品、季、剧集、文件及文件时间范围之间的关系，保存外部平台身份，支持一个文件包含多集等媒体布局。
- 接入 TMDB、Bangumi、弹弹play 等资料来源，支持搜索、批量获取和导入标题、简介、评分、演职员等信息，并记录资料来源。
- 提供显式匹配、重新绑定、作品合并、合并预览及符合条件时的撤回工具，方便整理重复作品和错误归属。
- Next 扫描和下载完成时登记文件事实；媒体身份由明确的匹配操作写入。Classic 已有匹配可通过专门入口导入。

### 可以按你的习惯整理的书架与图片

- 梨花可以建立首页书架，指定其中作品的排列顺序，并选择一部作品作为首页主视觉。
- 媒体库支持手选分类、按观看状态、类型、年份、评分等条件生成的分类，以及按原始来源浏览；可调整分类顺序、隐藏和恢复原始分类，切换卡片或书架形式。
- 支持用已有本地图片或图片链接设置作品海报、背景、Logo 和剧集截图，编辑标题与简介，也可以清除覆盖、恢复来源资料。

可以直接试着说：“把这几部按这个顺序放进‘周末想看’，首页大图用其中这一部。”或者：“用我给你的这张图替换它的背景。”

### 弹幕、字幕、下载与后台任务

- 弹幕支持来源搜索、身份绑定、立即准备、本地导入及持久保存。播放时复用已保存内容，按配置补充获取；普通缓存回收与持久弹幕分开管理。
- 字幕支持导入、来源记录、轨道选择和调整；弹幕提供启用、去重与时间偏移等控制。
- 下载支持磁力链接、种子和 HTTP 文件，可预览内容、选择文件、查看进度、暂停和继续，并在完成校验后登记文件。
- 梨花可以利用个人 Harness 中的资源发现工具搜索动画资源，比较不同版本、字幕组和下载来源，并通过可用的下载后端获取用户有权下载的内容，目前直接可用mikan进行资源搜索。
- 资源、弹幕和字幕的获取能力不限于预置来源。你可以要求梨花探索并接入新的可用来源，编写或改造获取工具，并将经过验证的脚本与操作经验保存到个人 Git Harness，供后续任务复用。
- 后台任务提供状态、事件、回执和后续通知入口。梨花可以跟进下载或整理任务，并在出现结果后继续工作。

可以直接试着说：“帮我找找这部动画有哪些可用的下载版本，比较一下字幕组，选好后下载并整理进媒体库。”或者：“现有工具找不到这部作品的字幕，试着寻找其他可用来源，完成后把有效的方法保存成工具。”

### Mesh：让不同设备参与同一项工作

- 同账号设备可以加入 Mesh，发现彼此、同步媒体目录，并通过直连传输媒体。视频可以留在工作站上，由另一台设备播放。
- 支持跨设备调用开放的应用能力，也可以将任务交给另一台设备上正在运行的梨花。
- 每台设备保有自己的数据库、个人仓库和记忆；操作在实际持有数据或能力的设备上执行。
- iPhone、iPad、Apple TV 和鸿蒙设备提供 Next 界面、播放器和 Mesh，通过桌面或其他宿主上的梨花完成对话与操作。Linux headless 提供适合服务器使用的无界面宿主。

### 面向开发者的能力与诊断

- 应用能力通过 `nipa` 命令行发现和调用；`list`、`describe` 可以查询目标设备当前提供的工具及参数，`--device` 指定 Mesh 设备。
- 保留本机及跨设备 SQL：查询结构与数据、预演修改、提交、查看回执，以及在满足条件时撤回。领域工具和 SQL 可用于不同粒度的整理任务。
- 提供任务、设备、来源、网络和播放器诊断，记录操作过程与关联标识，帮助梨花解释失败发生在哪一步。支持回执恢复的写入可以在响应丢失后查询提交结果。
- [逐项 Action 参考](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/development/ACTION_REFERENCE.md)列出全部源码动作；[场景指南](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/use/examples.md)提供更适合直接提出的请求示例。

### Alpha 1 的修复

本轮也修复了丰富元数据导致 Mesh 目录或 RPC 响应超限、目录同步失败被误判为设备离线、macOS Erika 打开远端视频时卡住等问题；改进了稳定播放身份与续播顺序、Classic 与 Next 的身份归属衔接、Mac 数据目录迁移和个人 harness 更新时的数据保留。

## 安装与开始使用

Release 附件提供以下版本：

- **macOS**：Apple Silicon、Intel 和 Universal，提供 DMG、PKG 与 ZIP。
- **Windows x64**：安装程序、ZIP 便携包与 MSIX。
- **Linux**：amd64 和 arm64 的 DEB、RPM 与 tar.gz；amd64 另提供 AppImage。
- **Linux headless**：amd64、arm64 的无界面宿主包，见 [Headless 指南](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/advanced/headless.md)。
- **iPhone / iPad**：当前附件为需自行签名侧载的 IPA；TestFlight 测试构建另行上传，开放测试的方式以发行页公告为准。
- **Apple TV**：需自行签名侧载的 tvOS IPA；TestFlight 测试构建与 iPhone 版同属一个 App。
- **鸿蒙**：已签名的 arm64 HAP。

本次发行不包含 Android。

安装后，在 Classic 的「设置 → 实验室」开启 NipaPlay Next，阅读风险提示并选择「我了解风险，开启」，即可直接进入 Next。桌面用户进入「设置 → 梨花」配置运行环境和模型服务，保存并测试连接后即可开始对话。iPhone、iPad 和 Apple TV 用户先在另一台设备上运行梨花，让两台设备同账号加入 Mesh，再选择远端梨花。

完整步骤见[下载与开启 Next](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/start/install.md)和[配置梨花](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/start/setup-nipa.md)。模型服务由用户自行配置，API 使用费用按所选服务商计费。

## 当前范围与已知问题

Next 目前仍以桌面体验和设备直连为重点。Mesh 需要双方地址可达，目前不提供 NAT 穿透或中继；手机、平板和电视使用远端梨花，本机不运行 Agent。完整的 Next 产品内备份恢复仍在开发，试用前请按[数据与恢复指南](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/advanced/data-and-recovery.md)保留应用数据和个人 harness 的副本。

持续更新的使用限制见[已知问题](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/help/known-issues.md)。欢迎提交 [Bug 报告](https://github.com/AimesSoft/NipaPlay-Reload/issues/new?template=bug_report.yml)，附版本、系统、复现步骤和关于页的诊断信息。Mesh 问题请附两端信息；公开内容请移除密钥、令牌及其他个人信息。

当前仍有以下差距：Next 播放器使用固定快捷键，尚不读取「快捷键」设置；Classic 的「跳过时间」未接入；字体库的导入界面和播放器内的手动匹配弹幕入口尚未完成（可在作品详情页的剧集管理中搜索匹配弹幕）；Erika 不支持调整字幕高度，MDK 只应用字幕颜色与粗细。
