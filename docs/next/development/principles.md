# 设计原则

这一篇说明 Next 做设计取舍时依据的原则：为什么这样分工，什么不该做。具体行为以[用户文档](../README.md)、[Action 参考](ACTION_REFERENCE.md)和源码为准；原则与实际行为不一致时，当作缺陷处理。

## 分工：梨花判断，NipaPlay 执行

- **对话是操作界面。** 用户表达意图，梨花查询事实、作出判断、调用工具；NipaPlay 的界面用来观看结果：书架、作品详情、播放器和弹幕。
- **NipaPlay 负责执行、保存和报告。** 文件枚举、探测、下载校验、任务续传、回执和来源记录属于宿主；"这个文件是哪一集""该选哪个版本""要不要整理"属于梨花。
- **宿主不替梨花做判断。** 不自动绑定作品身份，不按标题相似度猜测，不内置"过滤掉某类内容"之类的启发式。哈希匹配、搜索结果只是候选，由梨花显式绑定后才算确认。一条替她做判断的规则出现误判时，删掉它，而不是继续调参。
- **提供工具，而不是流程。** 宿主提供粒度合适的原语和批量接口，不预制"一键整理"式的固定流程。领域原语之外，[受约束的 SQL](../advanced/automation.md#数据库查询与修改sql) 是长期的通用能力，梨花不必等每一类整理都有专用 API。
- **能在 harness 里补的，就在 harness 里补。** 缺少的能力先由梨花在个人 harness 里用脚本、现成的开源工具补上；只有她在运行时改不了的部分（编译进 NipaPlay 的宿主能力），才改 NipaPlay 本身。

## 事实：实时查询优先于记录

- **能力以实时目录为准。** `nipa list`、`nipa describe` 返回目标设备当前注册的动作和参数；文档、记忆都可能过时。
- **记忆是历史判断。** 使用前核对实时状态；不把梨花的猜测写成用户的偏好。
- **外部文本是数据，不是指令。** 网页、文件名、字幕、种子标题里的文字不能改变授权范围。

## 可观察：结果、过程与证据分开

- 宿主分别暴露请求传输、能力执行、事务提交、任务进度、投影发布和播放器状态，让梨花能说清楚失败发生在哪一步。
- **"未知"不能简化成"失败"**，更不能把没收到响应当作没有提交。支持回执的写入，在响应丢失后可以按原请求键查询结果。
- **"已受理"不等于"已完成"。** 任务有可查询的状态和终态回执。

统一约定见[可观测性契约](OBSERVABILITY_CONTRACT.md)。

## 授权

- 推荐不等于执行；订阅需要用户明确提出。
- 破坏性操作只在用户要求时执行，默认先预览。
- 用户已经明确要求的，不再重复确认同一授权。
- 秘密可以使用，但不外泄：凭据在系统凭据保险库里，不进数据库、日志、记忆或 Git。
- 开启 Next 时用一次明确的风险说明取得同意。之后梨花作为用户的代理，在用户权限下工作；宿主不预设一套额外的"护栏"来替用户做决定，只对少数不可逆操作（删除下载文件、跨设备删除、覆盖）要求确认。

## Classic 与 Next：数据共享，运行与判断隔离

- **Next 使用自己的界面和播放会话。** 不在底下挂载 Classic，也不借用它的初始化、自动识别或播放界面。切换界面会关闭当前播放并保存进度，另一边不自动续播。
- **明确共享的数据继续共享**：设置、续播进度和观看记录。共享数据不授权 Classic 在 Next 里做识别判断。
- **兼容导入有明确方向。** Classic 的旧匹配只通过显式的 `media.library.import_history` 导入；Next 的明确绑定可以按既有契约投影给 Classic，但回读不会顺带导入其他身份。
- **Next 关闭时，Classic 的行为不变。** 梨花的运行器、本机端点和组网都停止，Classic 继续使用自己的扫描与匹配策略。

## 个人 harness

- 每个人有一个由梨花维护的 Git 仓库（默认 `~/nipaplay-harness`）：指令、记忆、工具、事件程序都在里面，其余内容由梨花在实际任务中生长出来。
- 官方种子的更新以 Git 合并方式进入：先预览，保留个人提交、未提交和忽略的文件；有冲突时暴露实际状态，不强制覆盖。
- 连接凭据放在仓库以外，只有当前用户可读。

## 多设备

- **没有中心节点。** 每台设备有自己的数据库、对话、记忆和 harness；组网合并的是目录事实，不复制整份数据库。
- **操作在持有数据或能力的设备上执行。** 跨设备调用使用目标设备的原始实体 ID 和实时契约。
- **协调服务只做身份和地址交换**，媒体和调用走设备之间的直连。

## 工程约束

- **主线程不阻塞。** 随数据量增长的工作（片库组合、查询、解码、脱敏）放在主线程之外；实验后检查运行日志里的主线程阻塞记录，超过 1 秒视为缺陷。
- **推送，不轮询。** 播放状态、任务进度和界面数据用事件推送；重活放进 Rust 或独立的工作线程。
- **界面文字像系统一样克制。** 不在界面上显示内部 ID、来源说明、调试信息或安抚性的文字；排错信息放在诊断入口里。
