# 工具指引与应用知识

工具接口承担一次调用所需的契约；应用知识解释软件机制。工具的副作用、完成含义、参数、确认和恢复信息，必须能直接从目标设备的工具接口发现，不要求先检索文档。

## 实时接口

`nipa list` 列当前注册的动作；`nipa describe ACTION` 返回该动作的 ActionSpec、宿主前置和 `usage`。`usage` 包含所属能力族的说明、effect 的含义、结果判读与未知结果恢复原则。`nipa describe FAMILY` 列该族的使用说明及已注册动作。

直接调用 `capability.describe {"family":"playback.kernel"}` 也可查询单个动作；family 字段兼容原有能力族查询。它读取接收端的注册目录，不执行被查询动作，也不依赖知识包。`knowledge.locate` 仅负责将同一实时契约连接到应用文档与静态源码引用。

远端 `nipa --device NAME describe ACTION` 向目标设备查询指引，不把本机版本的族说明贴到远端契约。远端结果附带 targetDeviceId、cliPrefix 和 commandScope，示例中的调用也应保留 --device。若目标不返回单动作契约，返回目录记录并标记 `guidanceStatus=catalogOnlyUnverified`；这可能是旧宿主或动作已移除，应刷新目录后使用。普通远程执行沿用目录中的 effect 路由，不因增加指引而多执行一次原操作。

## 一份工具指引需要回答什么

- 何时使用、何时应选择别的动作；对象 ID、路径、播放会话和配置属于哪台设备。
- 输入输出类型、必填条件、批量上限、分页方式和冲突校验。Schema 中合法不等于业务前置已经满足。
- 调用会修改什么，是否持久化、联网、产生文件或启动任务。read/write/destructive 分类不承诺可撤回、幂等或自动弹窗。
- 返回的是已受理任务还是最终结果；批量是否原子、如何逐项判断成功。completed 信封不能覆盖内部失败项。
- 授权与宿主确认是否分别需要；已有用户授权不应被重复索取，宿主拒绝也不能绕过。
- 失败后可查询哪些事实，是否有持久回执，原请求键和来源如何保留；取消、撤回、回滚各自意味着什么。

## 覆盖与维护

目前每个源码公开 Action 的顶层能力族都必须具有运行时族指引和安装包内的任务入口。`check_capability_docs.py` 检查源码候选与 Action 表；知识包生成器检查每个候选的能力族是否映射到已打包指南；测试检查运行时族说明及查询契约。参数和输出 Schema 来自实际 ActionSpec，避免在 Markdown 复制第二套参数表。

新增动作时评审单动作说明并更新任务入口；修改契约时更新 Schema、说明、族指引和受影响的应用知识。能力变更记录对标题、说明、input/output Schema 及族说明做指纹。上述检查能发现遗漏和未同步内容，不能代替逐项语义评审及真实任务验证。

按场景查[任务指南](guides/README.md)，理解机制查[应用模型](../reference/README.md)，安装版本知识的查询方式见[知识服务](../KNOWLEDGE.md)。
