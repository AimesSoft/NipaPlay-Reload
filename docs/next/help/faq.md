# 常见问题

先判断问题出在哪一层，再对症处理。梨花的一次工作涉及三层：

1. **模型**：决定要不要调用工具、调用哪个。模型拒绝或没想到调用工具，NipaPlay 什么也不会执行。
2. **工具**：NipaPlay 执行查询、下载、写入等操作。工具会成功、失败，或者结果未知。
3. **外部服务**：资源站、BT 网络、qBittorrent、Jellyfin、TMDB、其他设备。工具执行了，也可能被它们拒绝。

判断方法：看回答上方有没有**工作步骤**（「翻媒体库」「添加下载」之类）。

- **没有任何步骤**，只有一段文字：问题在模型这一层。
- **有步骤**，展开后看到错误、任务失败或回执里的错误：问题在工具或外部服务这一层，错误信息就是线索。

## 配置与模型

### 连接测试成功，但梨花不调用工具

「测试连接」只证明地址、密钥和模型名正确。用 Chat Completions 接口时，它甚至不要求模型真的调用工具（见[看懂"测试连接"](../start/setup-nipa.md#第三步看懂测试连接)）。真实对话里不调用工具，常见原因有：

- **模型的工具调用能力弱**，或者服务商的兼容接口对工具调用支持不完整。换成[推荐配置](../start/setup-nipa.md#推荐配置)里的模型试试。
- **接口选错了**。服务商同时提供两种接口时，Responses 的测试更严格：它要求模型真的发出工具调用。DeepSeek 官方接口应选 Responses。
- **模型 ID 指向了不支持工具的变体**，例如中转服务把同一个显示名称映射到别的模型。核对服务商文档里的 API 模型 ID。
- **问题本身不需要工具**。「你好」「解释一下 Mesh」这类问题，模型可以直接回答。用需要实时信息的问题测试，例如「播放器现在在放什么」。

排查顺序：换成推荐配置 → 测试连接 → 在对话里发一句需要查询的话，看有没有工作步骤出现。

### 运行环境一直下载不下来

「运行环境」显示「没能下载」时点「重试」。网络受限时，在「运行环境选项」里换镜像，或者用「使用指定的运行环境」指向已经装好的 Node.js 和 DSH。显示「这个平台暂时没有」时，说明没有为这个系统和架构预置运行环境，可以在另一台设备上运行梨花，再通过组网使用。详见[配置梨花](../start/setup-nipa.md#第一步准备运行环境)。

### 梨花回复很慢，或者费用很高

- 「思考」强度越高，每一步越慢、越贵。日常整理可以降到「低」。
- 对话越长，每次请求带的上下文越多。不相关的新话题，用[新的对话](../use/nipa.md#主对话与新的对话)开始。
- 批量任务会调用很多次工具，每次都是一次模型请求。先让她预览范围，确认后再执行。
- 费用由你的模型服务商结算，NipaPlay 不收费，也不统计账单。

## 下载

### 梨花拒绝帮我下载

先区分两种情况：

| 现象 | 说明 | 处理 |
|---|---|---|
| 只有文字回答，没有任何工作步骤，内容是"不能帮你下载"之类 | **模型在调用工具之前就拒绝了**。部分模型会因为安全策略拒绝 BT 资源相关的请求，NipaPlay 根本没有收到下载指令 | 说清楚内容来源和你的授权，例如"这是官方免费发布的资源"；仍然拒绝就换一个模型，或者在「动态」→「下载」里自己添加 |
| 有「添加下载」之类的步骤，展开后是错误 | **工具执行了，但出错**：认证、网络、下载器或磁盘问题 | 按下一节处理，换模型没有用 |

只下载你有权获取的内容。

### 下载器报错

「动态」→「下载」里，每个任务旁边有一个简短的状态，点开任务能看到已连接和已知的节点数、剩余空间：

| 状态 | 常见原因 | 处理 |
|---|---|---|
| 没有进展 | 连续一段时间没有新数据：没有可连接的节点（死种），或者网络被阻断 | 看任务里的已连接/已知节点数。节点数一直为 0，换一个资源；有节点但不动，检查网络和代理 |
| 找不到来源 | 拿不到种子的元数据，或者连接超时 | 磁力链接需要能连上 DHT 或 tracker。换一个带 tracker 的链接或种子文件 |
| 磁盘满了 | 下载位置空间不足 | 清理空间，或者在「存到」里换一个位置后「重试」 |
| 没有写入权限 | 下载位置不可写，或者 macOS 沙盒没有授予该目录 | 换一个目录，或者重新选择目录授权 |
| 没能下载 | 其他错误 | 让梨花查看这个任务的完整错误（`download.read`），或者复制诊断信息反馈 |

使用 qBittorrent 时，再检查：

- 「设置」→「下载」→「qBittorrent」里点「检查」，确认显示「连接正常」。「名称或地址不对」「连不上」说明 Web UI 地址、端口或登录信息有误；seedbox 常常还需要 HTTP Basic 认证。
- 远端 qBittorrent 下载完的文件在远端机器上，本机不能直接播放，需要取回或者通过 SMB、组网访问。

## 播放与设备

### 「这一集现在打不开」

播放器打开失败时显示这句话，片刻后退出。原因记在播放状态里，可以直接问梨花「刚才那集为什么打不开」，她能读取播放状态和诊断。常见原因：

- **文件不可读**：文件被移动、删除，网络共享断开，或者 macOS 没有授予目录访问权限。
- **来源设备离线**：只在另一台设备上的文件，那台设备不在线就打不开。
- **内核不支持这个格式**：在「设置」→「播放」→「播放器内核」换一个内核再试。
- **Jellyfin/Emby 登录失效**：「设置」→「媒体来源」里对应来源会提示「需要重新输入密码」。

能打开但播放异常（花屏、卡顿、没声音），在播放器「⋯」→「播放信息」底部点「复制诊断」，附在反馈里。

### 设备在线，但不能播放

组网里的调用和视频数据走同一条设备直连（mTLS），不经过服务器，也没有中继。设备列表里显示"在线"，说明最近一次直连成功了，所以问题通常不在"连不上"，而在下面几处：

1. **状态过时**：在线状态来自最近一次连接，对方可能刚刚睡眠、断网或退出。在对方设备上确认 NipaPlay 正在运行、Next 已开启。
2. **文件变了**：源设备上的文件被移动、改名或改写后，之前取得的播放地址会失效。让源设备重新扫描，再从媒体库重新打开。
3. **文件所在设备**：剧集菜单的「文件…」列出每个文件所在的设备。确认要播的那个文件确实在在线的设备上，而且那台设备上的 NipaPlay 有权读取它。
4. **播放端的本机转换**：播放端在 `127.0.0.1` 上开一个本机地址，把直连读到的数据交给播放内核。「设置」→「设备」里的「文件转换端口」被占用时会自动换成随机端口；可以让梨花查 `state.query mesh.file_proxy` 看实际状态。
5. **内核**：远端文件和本地文件一样受内核格式支持的限制，换一个内核再试。
6. **速度**：两台设备之间带宽不够时，表现为一直缓冲，而不是打不开。高码率文件尽量在同一局域网里播放。

如果设备一直显示不在线，才是直连本身的问题：两台设备要在同一局域网，或者通过 overlay 网络、SSH 转发等方式能直接连上；Windows 安装程序只为"专用"和"域"网络添加防火墙放行规则，公用网络或便携包需要自己放行；也可以在「设置」→「设备」里固定「端口」、补充「其他地址」。

反馈这类问题时，两台设备的信息都要附上：分别在「设置」→「关于」点「复制诊断信息」，并说明两边的网络环境，以及哪台是文件所在设备、哪台是播放设备。

### 弹幕没有出现

- 作品要先**匹配**好。弹幕按作品和剧集的身份获取；没有身份时，只有本地文件能用文件哈希在弹弹play 上唯一匹配到，才会自动获取。
- 不是每一集都有弹幕。可以在剧集菜单「弹幕…」里手动搜索、导入文件，或者让梨花准备。
- 检查播放器「弹幕」菜单里是否打开了弹幕、弹幕轨道是否被关掉。

## 任务与数据

### 任务超时了，到底写入没有？

网络中断、超时或设备失联时，一次写入的结果可能是**未知**（工具结果里的 `outcome_unknown`；和远端设备上的梨花对话时，显示「某某 没有回应，这句话可能已经送到了」）。

**未知不等于失败。** 请求可能已经送达并执行了，只是回复丢了。这时：

1. **不要立即重做**。重做可能导致重复下载、重复写入，甚至重复删除。
2. **查询实际状态**：后台任务看「动态」→「进行中」；写入操作查对应的回执，例如 SQL 修改查 `db.receipt`，作品绑定查 `media.identity.operation`。可以直接让梨花"查一下刚才那次写入有没有生效"。
3. **只有确认没有执行**，再重新提交。

"已受理"也不等于"已完成"：添加下载、开始扫描只代表任务已经提交，结果要看任务结束后的状态。

### 上下文压缩、记忆和历史有什么区别

- **对话历史**：完整保存，可以随时往上翻。
- **上下文压缩**：对话太长时，把较早的部分概括成摘要再交给模型。原始历史不变，但模型看到的是摘要，可能遗漏细节。
- **记忆**：她主动记下的偏好和经验，跨对话有效，在「梨花记得的事」里查看和删除。

重要的约定，让她"记下来"，比指望她从长对话里记住更可靠。详见[对话历史、上下文压缩和记忆](../use/nipa.md#对话历史上下文压缩和记忆)。

### 梨花做错了，怎么撤回

能不能撤回取决于具体操作：

- **作品身份认错**：在作品详情「匹配作品…」重新匹配，或者让她改正。
- **合并作品**：合并有回执，可以撤回。
- **SQL 修改**：用 `db.undo` 撤回，前提是相关的行在这之后没有再被改动。
- **设置**：「设置」→「梨花」→「梨花改过的设置」里可以撤销。
- **首页、书架、分类**：直接让她改回来，或者删掉。
- **删除的文件**：NipaPlay 不能恢复。所以删除文件需要你确认，批量操作前先要预览。她通过命令行或脚本删除的文件，也不能通过 NipaPlay 恢复。

### 回到经典界面，数据还在吗

在。「设置」→「经典界面」→「回到经典界面」只是切换界面。Next 的数据库、对话和梨花的文件夹都保留，下次开启 Next 时继续使用。部分设置、观看记录和进度是两边共用的。切换时会关闭当前的播放并保存进度，不会自动续播。
