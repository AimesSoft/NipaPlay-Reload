# 常见问题

梨花的一次工作涉及三层，排查时先确定出问题的一层：

| 层 | 职责 | 出问题时的表现 |
|---|---|---|
| 模型 | 决定是否调用工具、调用哪个 | 回答只有文字，没有工作步骤 |
| 工具 | NipaPlay 执行查询、下载、写入 | 工作步骤、任务或回执中出现错误 |
| 外部服务 | 资源站、BT 网络、qBittorrent、Jellyfin、TMDB、其他设备 | 工具的错误信息指向认证、网络或服务本身 |

## 配置与模型

### 连接测试成功，但梨花不调用工具

Chat Completions 接口的「测试连接」检查地址、密钥和模型名，不要求模型实际调用工具（见[测试连接](../start/setup-nipa.md#3-测试连接)）。真实对话中不调用工具的常见原因：

| 原因 | 处理 |
|---|---|
| 模型或服务商兼容接口的工具调用能力不足 | 改用[推荐配置](../start/setup-nipa.md#推荐配置) |
| 服务商同时提供两种接口，所选接口的工具调用较弱 | 改用 Responses；Responses 的测试要求模型实际发出工具调用 |
| 模型 ID 对应不支持工具的变体，例如中转服务的映射不同 | 按服务商文档核对 API 模型 ID |
| 请求本身无须工具，如「你好」 | 用需要实时信息的请求验证，如「播放器现在在放什么」 |

### 运行环境下载失败

「运行环境」显示「没能下载」时「重试」；网络受限时在「运行环境选项」中更换镜像，或用「使用指定的运行环境」指向已安装的 Node.js 和 DSH。「这个平台暂时没有」表示当前系统和架构没有预置运行环境，见[运行环境](../start/setup-nipa.md#1-运行环境)。

### 响应慢或费用高

- 「思考」强度越高，每一步越慢、费用越高。
- 对话越长，每次请求携带的上下文越多。无关的新话题使用[新的对话](../use/nipa.md#主对话与新的对话)。
- 批量任务的每次工具调用都是一次模型请求。
- 费用由模型服务商结算。

## 下载

### 梨花拒绝帮我下载

| 表现 | 原因 | 处理 |
|---|---|---|
| 只有文字回答，没有工作步骤 | 模型在调用工具前拒绝。部分模型的安全策略会拒绝 BT 资源相关的请求，NipaPlay 未收到下载指令 | 说明内容来源和授权；仍被拒绝时更换模型，或在「动态」→「下载」中直接添加 |
| 「添加下载」等步骤中出现错误 | 工具已执行，认证、网络、下载器或磁盘出错 | 见[下载器报错](#下载器报错) |

### 下载器报错

| 状态 | 常见原因 | 处理 |
|---|---|---|
| 没有进展 | 没有可连接的节点，或网络受阻 | 点开任务查看节点数：长期为 0 时更换资源；有节点但没有数据时检查网络和代理 |
| 找不到来源 | 无法获取种子元数据，或连接超时 | 磁力链接依赖 DHT 或 tracker，可改用带 tracker 的链接或种子文件 |
| 磁盘满了 | 下载位置空间不足 | 清理空间，或更换「存到」的位置后「重试」 |
| 没有写入权限 | 下载位置不可写 | 更换目录，或重新授予目录权限 |
| 没能下载 | 其他错误 | 请梨花读取任务的完整错误（`download.read`） |

使用 qBittorrent 时，在「设置」→「下载」→「qBittorrent」中「检查」：「名称或地址不对」「连不上」表示 Web UI 地址、端口或登录信息有误；seedbox 常需 HTTP Basic 认证。远端 qBittorrent 下载的文件位于远端机器，本机播放前需取回，或经 SMB、组网访问。

## 播放与设备

### 「这一集现在打不开」

打开失败时播放器显示这句话后退出，原因记录在播放状态中，可询问梨花「刚才那集为什么打不开」。常见原因：

| 原因 | 处理 |
|---|---|
| 文件被移动、删除，网络共享断开，或目录访问权限缺失 | 恢复文件或连接，重新扫描 |
| 文件所在设备离线 | 启动该设备上的 NipaPlay 并开启 Next |
| 当前内核不支持该格式 | 「设置」→「播放」→「播放器内核」更换内核 |
| Jellyfin、Emby 登录失效 | 「设置」→「媒体来源」中对应来源显示「需要重新输入密码」 |

能打开但画面、声音异常时，播放器「⋯」→「播放信息」→「复制诊断」，附在反馈中。

### 设备在线，但不能播放

组网的调用和视频数据经同一条设备直连（mTLS）传输。设备显示在线，表示最近一次直连成功。

| 原因 | 处理 |
|---|---|
| 在线状态来自较早的连接，对方已睡眠、断网或退出 | 确认对方的 NipaPlay 正在运行、Next 已开启 |
| 源设备上的文件已移动、改名或改写，原播放地址失效 | 源设备重新扫描后重新打开 |
| 文件位于其他设备，或源设备上的 NipaPlay 无权读取 | 剧集菜单「文件…」查看文件所在设备 |
| 播放端本机转换地址异常 | 「设置」→「设备」中的「文件转换端口」被占用时自动改用随机端口；梨花可查询 `mesh.file_proxy` 状态 |
| 内核不支持该格式 | 更换内核 |
| 设备间带宽不足 | 表现为持续缓冲；高码率文件在同一局域网内播放 |

设备持续显示不在线时，检查直连：两台设备需在同一局域网，或经 overlay 网络、SSH 转发直接可达；Windows 安装程序只为「专用」和「域」网络放行，公用网络和便携包需自行放行；可在「设置」→「设备」中固定「端口」、补充「其他地址」。

反馈时附两台设备各自的「复制诊断信息」，注明各自的网络环境，以及哪台是文件所在设备、哪台是播放设备。

### 弹幕没有出现

- 弹幕按作品与剧集的身份加载。作品尚未整理时，本地文件按弹弹play 文件哈希匹配，唯一命中时加载。请梨花整理该作品后重新播放。
- 部分剧集在弹幕来源中没有内容。剧集菜单「弹幕…」可手动添加或导入，「让梨花准备」交给梨花。
- 检查播放器「弹幕」菜单中的开关和「弹幕轨道」。

## 任务与数据

### 任务超时了，到底写入没有？

网络中断、超时或设备失联时，写入结果可能为未知：工具结果中显示 `outcome_unknown`；与其他设备上的梨花对话时，显示「某某 没有回应，这句话可能已经送到了」。此时请求可能已送达并执行。

1. 先查询状态：后台任务见「动态」→「进行中」；写入操作查对应回执，如 SQL 修改用 `db.receipt`，作品绑定用 `media.identity.operation`。也可以请梨花查询刚才的写入是否生效。
2. 确认未执行后再重新提交。

添加下载、开始扫描等操作提交的是后台任务，结果以任务结束时的状态为准。

### 上下文压缩、记忆和历史的区别

| | 说明 |
|---|---|
| 对话历史 | 完整保存，可随时查看 |
| 上下文压缩 | 对话超出预算时，较早部分以摘要交给模型，原始历史保留 |
| 记忆 | 梨花记录的偏好和经验，跨对话生效，在「梨花记得的事」中查看和删除 |

需要长期遵守的要求，请梨花写入记忆。详见[和梨花对话](../use/nipa.md#对话历史上下文压缩和记忆)。

### 撤回梨花的操作

| 操作 | 撤回方式 |
|---|---|
| 作品身份 | 在对话中说明正确的作品，或作品详情「匹配作品…」 |
| 合并作品 | 按回执撤回，前提是相关数据此后未再变化 |
| SQL 修改 | `db.undo`，前提同上 |
| 设置 | 「设置」→「梨花」→「梨花改过的设置」中进入对应设置项修改 |
| 首页、书架、分类 | 请梨花改回或删除 |
| 已删除的文件 | NipaPlay 无法恢复 |

### 回到经典界面后的数据

「设置」→「经典界面」→「回到经典界面」只切换界面。Next 的数据库、对话和个人 harness 保留，再次开启 Next 后继续使用。观看进度和部分设置两边共用；切换时当前播放关闭并保存进度。
