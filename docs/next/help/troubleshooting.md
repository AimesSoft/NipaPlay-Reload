# 故障排查

## 版本

「设置」→「关于」显示当前版本，「检查更新」查询新版本。已修复的问题见[已知问题](known-issues.md)和[更新说明](../release-notes.md)。各版本的限制见已知问题中的版本列。

## 诊断信息

| 问题 | 收集内容 | 位置 |
|---|---|---|
| 所有问题 | 应用诊断信息：应用版本、构建号、系统、运行架构、源码提交、所选播放内核 | 「设置」→「关于」→「测试与诊断」→「复制诊断信息」 |
| 播放 | 播放诊断：内核、来源、容器、编码、码率、解码方式 | 播放器「⋯」→「播放信息」→「复制诊断」 |
| 梨花运行失败 | 原始错误 | 「梨花运行失败」提醒 →「复制完整错误」 |
| 梨花的行为 | 原始请求、工作步骤和工具输出 | 对话中展开对应的工作步骤 |
| 组网 | 两台设备各自的应用诊断信息和网络环境 | 分别在两台设备上复制 |
| 下载 | 任务状态、节点数、下载后端 | 「动态」→「下载」→ 点开任务 |

梨花可以读取播放状态、任务、回执和日志，整理反馈所需的信息：

> 整理反馈刚才播放失败所需的诊断信息。

## 日志

- 应用日志写入应用存储目录下的 `logs/`，保留最近 5 份。开关：「设置」→「通用」→「诊断」→「写入日志文件」。
- 梨花可读取和导出日志（`diagnostics.logs`、`diagnostics.export`），查询日志目录（`diagnostics.directory`）。
- [Linux 无界面版](../advanced/headless.md)的日志在 systemd journal：`journalctl --user -u nipaplay-headless`。
- 事件程序和定时程序的输出记录在对应的 `harness.hook` 任务回执中，见[自动化与个人工具](../advanced/automation.md#事件程序)。

## 提交反馈

GitHub [提交 Issue](https://github.com/AimesSoft/NipaPlay-Reload/issues/new/choose)，选择「Bug 报告」：

- 「产品版本线」选择「Next 开发者预览」。
- 「复现步骤」写明起始页面、操作和对梨花说的话。
- 「Next、Mesh 或 DSH 信息」填入诊断信息；与梨花相关时，写明运行器、模型、服务商和接口类型。
- 截图和录屏在 Issue 创建后于评论中上传。

## 隐私

诊断信息、日志和工具输出中可能包含个人信息。提交前删除：

- API key、密码、令牌、cookie；
- `endpoint.json` 的内容；
- 文件路径、用户名、局域网和公网地址中不公开的部分；
- 对话中的私人内容。

NipaPlay 在日志和工具输出中遮蔽已知凭据，其他敏感内容需提交者检查。
