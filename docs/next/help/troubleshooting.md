# 故障排查

[常见问题](faq.md)里没有答案时，按这一篇收集信息并反馈。信息越完整，越快能定位。

## 1. 先确认版本

「设置」→「关于」显示当前版本，可以点「检查更新」。问题可能已经在新版本修复，可以先看[已知问题](known-issues.md)和[更新说明](../release-notes.md)。

文档跟随 `next` 开发分支。已安装的版本较旧时，以对应版本标签下的文档为准。

## 2. 收集诊断信息

| 问题类型 | 收集什么 | 在哪里 |
|---|---|---|
| 所有问题 | 应用诊断信息：应用版本、构建号、系统、运行架构、源码提交、所选播放内核等 | 「设置」→「关于」→「测试与诊断」→「复制诊断信息」 |
| 播放问题 | 播放诊断：内核、来源、容器、编码、码率、解码方式等 | 播放器「⋯」→「播放信息」→「复制诊断」 |
| 梨花运行失败 | 完整错误 | 对话里的「梨花运行失败」提醒 →「复制完整错误」 |
| 梨花做错了事 | 你说的原话、她的工作步骤和工具输出 | 对话里展开对应的工作步骤，复制或截图 |
| 组网问题 | **两台设备**各自的应用诊断信息，以及网络环境 | 分别在两台设备上复制 |
| 下载问题 | 任务状态、节点数，使用的后端（内置或 qBittorrent） | 「动态」→「下载」→ 点开任务 |

也可以直接让梨花帮你收集：「我要反馈刚才播放失败的问题，帮我整理诊断信息」。她能读取播放状态、任务、回执和日志。整理完后先检查一遍内容再发出。

## 3. 日志

- 应用日志默认写入应用存储目录下的 `logs/`，保留最近 5 份。开关在「设置」→「通用」→「诊断」→「写入日志文件」。
- 梨花可以读取和导出日志（`diagnostics.logs`、`diagnostics.export`），也能告诉你日志目录（`diagnostics.directory`）。
- [Linux 无界面版](../advanced/headless.md)的日志在 systemd journal：`journalctl --user -u nipaplay-headless`。
- 事件程序和定时程序的输出记在对应的 `harness.hook` 任务回执里，见[自动化与个人工具](../advanced/automation.md#事件程序)。

## 4. 提交反馈

在 GitHub [提交 Issue](https://github.com/AimesSoft/NipaPlay-Reload/issues/new/choose)，选「Bug 报告」：

- 「产品版本线」选「Next 开发者预览」。
- 「复现步骤」写清楚从哪个页面开始、点了什么、对梨花说了什么。
- 「Next、Mesh 或 DSH 信息」粘贴上面收集的诊断信息；梨花相关的问题，写明运行器、模型和服务商、接口类型。
- 截图和录屏可以在 Issue 创建后，在评论里上传。

## 5. 隐私

诊断信息、日志和工具输出里可能包含个人信息。发出前检查并删除：

- API key、密码、令牌、cookie；
- `endpoint.json` 的内容（本机连接凭据）；
- 不想公开的文件路径、用户名、局域网和公网地址；
- 对话里涉及的私人内容。

NipaPlay 在日志和工具输出里会遮蔽已知的凭据，但不能保证遮蔽所有敏感信息。拿不准时，先删掉再发。
