# NipaPlay Next · Developer Preview

这是 NipaPlay Next 的第二个开发者预览（Alpha 2）。Next 重新组织了媒体库、播放器和个人助手之间的关系：你通过对话表达想做的事，梨花查询信息、选择工具并执行，结果呈现在书架、作品资料、播放器和弹幕里。

Alpha 2 补齐了播放器菜单与 Classic 的差距，让 Erika 成为可选内核并升级到 0.3.2，扩充了作品详情页，并把资料的展示方式交给梨花按你的要求调整。下面先列出本次更新，随后是 Next 的完整功能介绍。

本次预览由 **AimesSoft** 发布，面向开发者、Agent 系统爱好者，以及愿意一起探索这种使用方式的用户。

> [!CAUTION]
> **⚠️ 高风险实验性软件 · 仅供具备相关技术经验的用户测试**
>
> **NipaPlay Next 是具有完整用户级系统权限的 AI Agent 实验，而非面向普通用户的稳定版播放器。** 本次发布仅面向开发者、Agent 系统研究者及充分了解相关风险的技术爱好者。如果你不熟悉系统权限、Agent 行为及数据恢复，请继续使用 NipaPlay Classic。
>
> **Agent 具有广泛的系统操作能力。** 梨花可以在应用进程及当前用户拥有的权限范围内读写、覆盖和删除文件，运行程序、联网，并使用可访问的账号和登录状态。它的操作范围可以超出 NipaPlay 媒体库；不要将它视为只会回答问题的聊天窗口，也不要假定所有操作都会再次弹窗确认。
>
> **风险同样延伸到 Mesh 和内网设备。** 加入组网意味着信任同账号认证设备访问本机开放的能力和应用进程可访问的文件；启用远程程序运行后，其他设备上的 Agent 还可以在本机执行程序。处于同一局域网并不意味着安全，设备认证也不能防止已经受信任的 Agent 作出错误操作。
>
> **模型行为不可完全预测，错误操作可能造成不可逆的损失。** 模型误判、软件缺陷，以及网页、文件名、字幕等外部内容中的恶意指令，都可能引发数据丢失、隐私或凭据泄露、账号操作和额外费用。关闭 Next、切换回 Classic 或卸载应用，都不能自动撤销 Agent 已经执行的操作。
>
> **请仅在可承受损失的测试环境中使用。** 强烈建议使用隔离的测试设备、独立系统账号和可丢弃的数据副本，保留离线备份，只加入可信设备。**不要在存放唯一重要数据的主力电脑、工作设备或关键业务环境中直接试用。** 当前 Next 尚未提供完整的产品内备份与恢复能力。
>
> **注意模型服务的数据传输。** 模型服务会接收任务所需的对话与工具结果，其中可能包含文件内容、路径或其他敏感信息。请自行选择可信的服务商，了解其数据政策及可能产生的 API 费用。
>
> **如果你无法独立处理系统故障、检查 Agent 操作或恢复重要数据，请勿启用本次 Alpha 实验。**


## Alpha 2 更新了什么

### 播放器：点下就有反馈，菜单对齐 Classic

- 点击播放后立即进入播放画面，显示片名和加载状态，不再停在原页面等待地址解析和 Mesh 请求；打不开时直接说明，左上角返回可取消这次打开。弹幕改为在后台准备，不再挡住开播。
- 字幕菜单新增「样式」与「字幕列表」：颜色、字体、粗体斜体、不透明度、描边、阴影、位置、水平与垂直对齐、边距，以及 ASS 字幕的样式覆盖；只列出当前绘制这条字幕的内核真正能改的项。字幕列表列出全部台词，点击跳转。
- 弹幕菜单新增速度、合并相同弹幕，以及样式（描边、粗细、阴影、字体、轨道间距、堆叠、随机颜色）、屏蔽词、弹幕轨道（开关、移除、添加本地文件）、弹幕列表（点击跳转）、发送弹幕、保存为 JSON / XML 和恢复默认。
- 「⋯」菜单新增倍速手动输入、播放设置（快进快退步长、长按 → 倍速、进度条预览、弹幕密度）、Jellyfin / Emby 串流清晰度，以及播放信息（内核、来源、分辨率、编码、码率、音频）与一键复制诊断。
- 右方向键与 Classic 一致：单击快进，长按按设定倍速播放、松开恢复；播放中修改快进步长立即生效。
- Media Kit 内核现在真正应用共享的字幕样式（位置、对齐、边距、描边粗细、阴影、字体、样式覆盖）；字幕不透明度对内核字幕生效。

### Erika 成为可选的播放内核

- Erika 离开实验室：在支持 Erika 的平台上，播放器内核选项直接提供 Erika，不再需要实验室开关。
- 升级到 Erika 0.3.2：从续播位置直接打开，首帧就是续播处；播放结束由内核明确报告；支持字幕时间偏移和读取当前台词。
- 选择 Erika 时，弹幕与 Classic 一样由 Erika 自己绘制在画面里，弹幕设置照常生效；设置页随之不再显示弹幕渲染引擎。
- Next 中的 Erika 现在应用字幕样式：颜色与不透明度、描边、阴影、粗体斜体、对齐、边距、字体（含字体库中的字体文件）与 ASS 样式覆盖。

### 作品详情页：演职人员、图片与完整资料

- 剧集之后新增演职人员、角色与声优、剧照与海报（可全屏查看）、完整资料（原名、首播与完结、状态、季数集数、制作公司、电视网、主创、国家与语言、预算票房、标签）和外部链接。
- 点开演职人员进入人物页：照片、生卒与出生地、简介、在媒体库中的作品和参与作品。
- 同一项资料常有多个来源（TMDB、Bangumi、弹弹play 的标题、简介、评分等）。梨花现在知道页面每个位置显示的是哪个来源的哪项资料，可以按你的要求改用其他来源、调整评分显示、区块顺序和每行数量，对全部作品或单部作品生效。

可以直接试着说：「这部的简介改用 Bangumi 的，评分只显示 Bangumi。」或者：「详情页先放角色，再放演职人员，图片放最后。」

### 梨花的提醒与提问

- 提醒与提问改为与 Next 一致的卡片：多条可同时显示和切换，可收起为一条小提示；提醒会持久保存，不会因关闭窗口而丢失；添加文件夹后的整理提示在后台进行。
- 提醒不再遮挡播放控件；GIF 截取、分离窗口、粘贴提示等最后几处旧样式窗口改为 Next 风格。

### 下载、来源与授权

- qBittorrent 后端可在设置中管理，seedbox 支持 HTTP Basic 认证。
- Jellyfin、Emby 等外部来源的作品、季、剧集与资料持久保存，可与本地作品统一管理。
- 受保护的网络设置可在对话中由你明确授权后交给梨花配置；凭据登录仍通过 NipaPlay 自己的登录窗口完成。
- 同一 Mesh 下各设备的后台任务统一显示：例如 Windows 上正在进行的下载，在 Mac 的后台面板和「动态」里也能看到，并标注所在设备；这些任务在它所在的设备上暂停或取消。

### 修复

- 阅读授权提示并同意后直接进入 Next；设置页保持响应，缓存清理范围与设置一致；「首页」导航回到概览。
- 启动时等待图形界面的 harness 就绪后再调用；空媒体库在作品到达时刷新；读取期间到达的片库更新不再丢失。
- 下载恢复后每个会话只显示一个条目；任务更新与观察衔接；原生复检时复用已完成的下载任务。
- 补全元数据获取指引；修复 Mesh 播放恢复；macOS 公证检查保留缓存并报告签名诊断。
- 下载任务显示真实名称，重试或失败时显示原因；梨花读取图片不再先探测模型是否支持图片输入；收起提醒在本机立即生效，不再等待远端调用。

## 我们希望探索什么

整理媒体往往是一连串具体判断：文件是哪一集、几个版本该选哪个、资料应该如何补齐、哪台设备能提供视频、怎样把片库摆成自己喜欢的样子。我们希望用户能够直接表达目标，让 Agent 根据当下的文件、来源和设备状态完成这些工作。

这也是 Next 的分工：**梨花负责理解和判断，NipaPlay 负责具体执行、保存数据和报告结果。** 文件识别工具提供候选，明确的匹配操作建立作品归属；下载、播放和后台任务有可查询的状态，资料修改保留来源，支持的写入提供预览与回执。图形界面承载观看体验，也让对话中的操作有看得见的结果。

每个人还拥有自己的 **Git harness**——一个保存工具、脚本、偏好和操作经验的个人仓库。梨花可以在实际任务中维护它，复用已有工具、补充脚本，记录适合你的工作方式。经验随着使用积累，你也可以打开文件查看、修改和管理 Git 历史。

## Next 的功能（Alpha 1 起）

### 独立的 Next 界面与播放器

- 新增首页、媒体库、作品详情、对话和播放界面，将观看内容与梨花的工作结果放在同一套体验中。
- 首页呈现继续观看、最近播放和自定义书架；作品详情汇集剧集、资料、图片和播放来源。
- 提供独立播放会话与内核控制，支持续播、定位、音轨和字幕轨道选择，以及本地和 Mesh 远端媒体播放。
- 保留 Classic。可在设置中切换两套界面，部分设置、观看记录与续播进度继续共用；切换时保存进度并关闭当前播放会话。

### 梨花对话与个人工作环境

- 接入 DeepSeek Harness（DSH）和 Codex 会话运行器。桌面设置提供 DSH 运行环境下载，以及模型服务商、接口地址、模型和 API key 配置。
- 对话支持流式输出、图片附件、工作过程查看和作品、剧集、任务等结果卡片。
- 完整历史采用渐进加载，向上翻阅可以继续读取早期回合；DSH 提供上下文压缩，个人记忆另行保存在可查看和编辑的文件中。
- 开放 DSH 高级配置，包括上下文预算、压缩和插件设置，并提供配置文件编辑入口。
- 个人 harness 保存工具、记忆和事件脚本；官方种子更新会保留个人修改，遇到合并冲突时报告状态。可通过 hooks 和定时程序安排后续工作。

### 媒体身份、资料与整理

- 建立作品、季、剧集、文件及文件时间范围之间的关系，保存外部平台身份，支持一个文件包含多集等媒体布局。
- 接入 TMDB、Bangumi、弹弹play 等资料来源，支持搜索、批量获取和导入标题、简介、评分、演职员等信息，并记录资料来源。
- 提供显式匹配、重新绑定、作品合并、合并预览及符合条件时的撤回工具，方便整理重复作品和错误归属。
- Next 扫描和下载完成时登记文件事实；媒体身份由明确的匹配操作写入。Classic 已有匹配可通过专门入口导入。

### 可以按你的习惯整理的书架与图片

- 梨花可以建立首页书架，指定其中作品的排列顺序，并选择一部作品作为首页主视觉。
- 媒体库支持手选分类、按观看状态、类型、年份、评分等条件生成的分类，以及按原始来源浏览；可调整分类顺序、隐藏和恢复原始分类，切换卡片或书架形式。
- 支持用已有本地图片或图片链接设置作品海报、背景、Logo 和剧集截图，编辑标题与简介，也可以清除覆盖、恢复来源资料。

可以直接试着说：“把这几部按这个顺序放进‘周末想看’，首页大图用其中这一部。”或者：“用我给你的这张图替换它的背景。”

### 弹幕、字幕、下载与后台任务

- 弹幕支持来源搜索、身份绑定、立即准备、本地导入及持久保存。播放时复用已保存内容，按配置补充获取；普通缓存回收与持久弹幕分开管理。
- 字幕支持导入、来源记录、轨道选择和调整；弹幕提供启用、去重与时间偏移等控制。
- 下载支持磁力链接、种子和 HTTP 文件，可预览内容、选择文件、查看进度、暂停和继续，并在完成校验后登记文件。
- 梨花可以利用个人 Harness 中的资源发现工具搜索动画资源，比较不同版本、字幕组和下载来源，并通过可用的下载后端获取用户有权下载的内容，目前直接可用mikan进行资源搜索。
- 资源、弹幕和字幕的获取能力不限于预置来源。你可以要求梨花探索并接入新的可用来源，编写或改造获取工具，并将经过验证的脚本与操作经验保存到个人 Git Harness，供后续任务复用。
- 后台任务提供状态、事件、回执和后续通知入口。梨花可以跟进下载或整理任务，并在出现结果后继续工作。

可以直接试着说：“帮我找找这部动画有哪些可用的下载版本，比较一下字幕组，选好后下载并整理进媒体库。”或者：“现有工具找不到这部作品的字幕，试着寻找其他可用来源，完成后把有效的方法保存成工具。”

### Mesh：让不同设备参与同一项工作

- 同账号设备可以加入 Mesh，发现彼此、同步媒体目录，并通过直连传输媒体。视频可以留在工作站上，由另一台设备播放。
- 支持跨设备调用开放的应用能力，也可以将任务交给另一台设备上正在运行的梨花。
- 每台设备保有自己的数据库、个人仓库和记忆；操作在实际持有数据或能力的设备上执行。
- iPhone/iPad 提供 Next 界面、播放器和 Mesh，通过桌面或其他宿主上的梨花完成对话与操作。Linux headless 提供适合服务器使用的无界面宿主。

### 面向开发者的能力与诊断

- 应用能力通过 `nipa` 命令行发现和调用；`list`、`describe` 可以查询目标设备当前提供的工具及参数，`--device` 指定 Mesh 设备。
- 保留本机及跨设备 SQL：查询结构与数据、预演修改、提交、查看回执，以及在满足条件时撤回。领域工具和 SQL 可用于不同粒度的整理任务。
- 提供任务、设备、来源、网络和播放器诊断，记录操作过程与关联标识，帮助梨花解释失败发生在哪一步。支持回执恢复的写入可以在响应丢失后查询提交结果。
- [逐项 Action 参考](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/development/ACTION_REFERENCE.md)收录 315 个源码动作；[场景指南](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/NIPA_CAPABILITIES.md)提供更适合直接提出的请求示例。

### Alpha 1 的修复

本轮也修复了丰富元数据导致 Mesh 目录或 RPC 响应超限、目录同步失败被误判为设备离线、macOS Erika 打开远端视频时卡住等问题；改进了稳定播放身份与续播顺序、Classic 与 Next 的身份归属衔接、Mac 数据目录迁移和个人 harness 更新时的数据保留。

## 安装与开始使用

Release 附件提供以下版本：

- **macOS**：Apple Silicon、Intel 和 Universal，提供 DMG、PKG 与 ZIP。
- **Windows x64**：安装程序、ZIP 便携包与 MSIX。
- **Linux**：amd64 和 arm64 的 DEB、RPM 与 tar.gz；amd64 另提供 AppImage。
- **Linux headless**：amd64、arm64 的无界面宿主包，见 [Headless 指南](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/HEADLESS.md)。
- **iPhone / iPad**：当前附件为需自行签名侧载的 IPA；TestFlight 分发正在准备，开放信息将在发行页更新。

本次发行不包含 Android、tvOS 和 HarmonyOS。

安装后，在 Classic 的「设置 → 实验室」开启 NipaPlay Next，阅读风险提示并选择「我了解风险，开启」，即可直接进入 Next。桌面用户进入「设置 → 梨花」配置运行环境和模型服务，保存并测试连接后即可开始对话。iPhone/iPad 用户先在另一台设备上运行梨花，让两台设备同账号加入 Mesh，再选择远端梨花。

完整步骤见[快速开始](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/QUICKSTART.md)。模型服务由用户自行配置，API 使用费用按所选服务商计费。

## 当前范围与已知问题

Next 目前仍以桌面体验和设备直连为重点。Mesh 需要双方地址可达，目前不提供 NAT 穿透或中继；移动端使用远端梨花，本机不运行 Agent。完整的 Next 产品内备份恢复仍在开发，试用前请按[数据与恢复指南](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/DATA_AND_RECOVERY.md)保留应用数据和个人 harness 的副本。

持续更新的使用限制见[已知问题](https://github.com/AimesSoft/NipaPlay-Reload/blob/next/docs/next/KNOWN_ISSUES.md)。欢迎提交 [Bug 报告](https://github.com/AimesSoft/NipaPlay-Reload/issues/new?template=bug_report.yml)，附版本、系统、复现步骤和关于页的诊断信息。Mesh 问题请附两端信息；公开内容请移除密钥、令牌及其他个人信息。

Alpha 2 中仍有以下差距：Next 播放器使用固定快捷键，尚不读取「快捷键」设置；Classic 的「跳过时间」未接入；字体库的导入界面和播放器内的手动匹配弹幕入口尚未完成（可在作品详情页的剧集管理中搜索匹配弹幕）；Erika 不支持调整字幕高度，MDK 只应用字幕颜色与粗细。
