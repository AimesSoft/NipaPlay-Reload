# 隐私与数据

NipaPlay 尊重你的隐私。以下说明应用在不同场景下的数据处理方式。

## 本地数据

- 播放记录、设置、观看历史默认保存在本机（SQLite + SharedPreferences）。当前版本仍有部分服务凭据和远程控制信任信息保存在 SharedPreferences；这属于已知安全债务，不应把设备级偏好设置视为安全密码库。
- 不会在未经你操作的情况下上传到任何服务器。

## 网络请求

NipaPlay 在以下功能中会发起网络请求：

- **弹弹play**：匹配弹幕时会向弹弹play API 发送视频文件的哈希和文件名，用于获取匹配的弹幕数据。登录后会同步观看进度。
- **Bangumi**：配置访问令牌后，会与 bgm.tv API 通信以同步收藏、进度和评分。
- **Emby / Jellyfin**：连接媒体服务器时，身份认证和媒体元数据在你自己的服务器端处理。
- **AI 防剧透**：如果你启用了此功能，弹幕文本会被发送到你配置的 AI API 端点（OpenAI 兼容接口或 Google Gemini）进行分析。请确认你信任所配置的 API 服务商。
- **JS 插件**：第三方插件可能会发起网络请求，请注意审查插件来源。

## 凭据与访问令牌

WebDAV、SMB、Emby、Jellyfin、Bangumi、弹弹play、AI 接口和远程控制都可能涉及凭据或 token。配置前请确认服务端地址和证书可信；不要把包含密码、token 或完整远程地址的配置文件提交到仓库或公开分享。

在迁移到系统安全存储完成前，建议：

- 使用独立、低权限的媒体服务器账号；
- 为远程控制设置强随机口令，并避免把 Web server 暴露到公网；
- 分享日志前删除 URL 中的用户名、密码、token、局域网地址和本地路径；
- 卸载前在应用设置中清理服务器、账号、token 和远程设备授权。

## 本地 Web server 与远程控制

启用 Web server 或远程控制后，局域网内其他设备可能访问播放器状态、媒体列表或控制接口。请仅在可信网络中开启，使用完毕后关闭，并检查监听地址、端口和已授权设备列表。NipaPlay 不应被当作带有公网身份认证、TLS 和审计能力的通用反向代理。

## 日志

- 日志用于排障，可能包含文件路径、服务器地址等信息。
- 分享日志前请检查是否包含敏感信息。
